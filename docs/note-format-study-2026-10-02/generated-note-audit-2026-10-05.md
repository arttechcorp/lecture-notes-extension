# 실제 생성 노트 검토와 수정 명세

2026-10-05 · 대상: 사용자가 제공한 PDF 24쪽과 Markdown, 같은 packageId의 콘텐츠 없는 진단 기록, 현재 `w/dev` 코드. 검토 중 체크아웃은 `50e2e9f`까지 갱신됐다. 제품 코드는 변경하지 않았다.

## 1. 결론과 확인 범위

현재 제품에는 Note 계약과 B타입별 템플릿이 이미 구현돼 있다. 10월 2일 전달 문서의 “Plan/Note 미구현”은 당시 상태이며 지금의 진단으로 사용하면 안 된다.

문제는 색상 부족이 아니다. 브랜드 토큰은 상당 부분 반영됐지만, **원본 교재의 계층적 설명과 비교 중심 편집, 페이지 안에서 내용을 묶는 조판, 시각 자료의 품질 관리**가 충분히 구현되지 않았다. 여기에 실제 검증 탈락으로 인한 내용 누락이 겹쳤다.

PDF 전체를 축소 지면으로 확인하고 수식 페이지 및 PDF에 내장된 수식 이미지를 확대 확인했다. IMFACT·LIMIT 원본 첫 지면과 기존 v3 인쇄 시안도 다시 비교했다. 이미지 렌더링은 메모리에서 수행했다. 강의 원문·전사·슬라이드나 생성 노트 본문을 이 보고서에 복제하지 않는다.

이 자료만으로 강의 원문 대비 누락률이나 각 설명의 사실성을 확정할 수는 없다. 암호화 패키지를 복호화하거나 강의 원본을 다시 가져오지는 않았다. 진단의 코드·건수는 확인했지만 낮은 근거 점수 20건이 모두 정당한 탈락인지까지 판정한 것은 아니다.

## 3. 내용이 비는 현상은 세 가지다

### 3.1 작성 후 검증에서 빠진 내용

같은 강의 진단 기록의 버전은 `1.3.6`이다. 결과 고지와 일치하는 다음 기록을 확인했다.

- `SUPPORT_SCORES`: 284개 주장 판정, 기준 미달 20개, 블록 보류 5개, 개별 주장 제거 6개. 이 건수들은 서로 다른 집계 단위이므로 합산하지 않는다.
- `BLOCKS_HELD`: writer=0, server=4, judge=5. server 값은 재작성 전 집계이므로 최종 누락에 그대로 더하지 않는다.
- 최종 `BLOCKS_DROPPED`: `VAL_BLOCK_DECLINED=5`, `VAL_ANSWER_SHAPE=1`.
- 결과 고지: 블록 6건, 종속 항목 4건 제거, 미인용 강의 구간 5곳.
- `HELD_WHY`에는 targetIds/reviewIds 최소 항목 부족, n1 같은 지도 노드 ID를 targetIds에 사용한 오류가 있음.
- Writer 출력 잘림 3건과 timeout 2건에 대한 분할 기록도 있음. 발생했다는 사실만으로 최종 내용 누락이라고 단정하지 않는다.

현재 `lib/stages.js:405` 이후는 낮은 근거 점수를 받은 선택 슬롯을 비우거나 목록 항목을 제거한다. 필수 슬롯이면 블록 전체가 보류될 수 있다. 따라서 “모델이 빈 내용을 작성했다”로만 설명하는 것은 틀리다.

수정:

1. 기존 내용을 무조건 통과시키거나 threshold만 낮추지 않는다.
2. 모델에 허용 targetIds/reviewIds를 블록별로 명시하고, 노드 key와 문서 참조 ID를 구분한다. 가능한 범위에서 요청별 enum을 재사용한다.
3. 근거 부족을 인식 실패 / 잘못 연결된 근거 / 번역 의미 변화 / 주장 과장 / 실제 미지원으로 구분한다. 단순 숫자 일치로 사실성을 판정하지 않는다.
4. T5 근거 판정 이후에도 근거가 있는 최소 주장으로 고칠 여지가 있는 경우에만, 기존 재시도 예산 안에서 표적 재작성과 재검증을 수행한다. 전체 단원을 무제한 재생성하지 않는다.
5. 필수 개념·조건·수식이 보류된 단원은 해당 위치에서 범위와 이유를 짧게 알린다. 끝의 합계만으로 끝내지 않는다.
6. 유닛 인용 비율과 학습 내용 충족률을 구분한다. 필수 개념의 정의, 비교 기준, 적용 조건이 살아 있는지 따로 확인한다.

### 3.2 편집상 빈약하거나 반복되는 설명

JSON 슬롯이 존재한다는 것과 설명이 구조화됐다는 것은 다르다. 현 프롬프트는 타입과 금지를 자세히 규정하지만, 슬롯별 편집 목적·중복 방지·개념 간 대비를 충분히 강제하지 않는다.

- B05: 정의=무엇인가, 풀이=어떻게 이해할까, 원리=왜 그런가, 조건=언제 성립하는가로 역할을 분리한다. 같은 뜻을 표현만 바꿔 네 번 쓰지 않는다.
- 같은 비교 축을 가진 개념은 B06 한 표에 모은다. 독립 정의는 짧게 두고 표를 다시 문단으로 전부 반복하지 않는다.
- B07은 단순 목록과 실제 인과·논증을 구분한다. 순서에 불과한 관계에 causes/supports를 강제하지 않는다.
- B03은 연결당 짧은 관계를 하나만 표시한다. 상세 주장은 본문에 두고 동일 간선·주장을 반복하지 않는다.
- B02 전체 요약은 앞쪽 단원의 사실 세 개로 끝내지 않고 강의 전체 질문에 답해야 한다. 세 항목 한도를 유지해도 여러 단원을 상위 명제로 묶을 수 있다.
- 퀴즈 수는 전체 계획에서 배분한다. 현재 “전체 4–8개 권장”은 조판 advisory에 그치며 출력은 15문항이다. 문항을 만들고 나서 무작정 잘라내지 않는다.
- 영어 표 크롭은 근거 자료다. 한국어 요약표와 학습 해석을 대신하게 두지 않는다. 이해에 필요할 때만 원본을 인접 참조로 붙인다.
- 외부 보강·가상 사례는 기존 옵션 정책을 유지한다. 빈 영역을 채우려고 근거 없는 설명을 추가하지 않는다.

### 3.3 조판이 만든 여백

고정 답안 칸, 문단 전체의 break-inside:avoid, 큰 다음 요소를 밀어낸 결과는 내용 누락과 구분한다. 읽기형 PDF의 기본값은 불필요한 답안 칸 없음으로 두고, 필기 모드에서 문항 유형별 공간을 부여한다. 참고 교재에도 의도한 필기 여백은 있지만, 모든 문항에 같은 빈 상자가 반복되지는 않는다.

## 4. 레퍼런스에 가까운 실제 지면 규칙

브랜드 v3의 색·서체를 유지하면서 IMFACT의 계층과 학습 순서, LIMIT의 속성 표·주석·자료 해석 구분을 옮긴다. 색을 원본의 다색 체계로 되돌리는 것이 우선은 아니다.

| 구성 | 실행할 지면 규칙 |
|---|---|
| 단원 시작 | 큰 단원 번호 → 핵심 질문 → 한 줄 요지. 제목과 첫 내용 묶음이 같은 쪽에 시작 |
| 개념 | 번호 있는 개념명, 완결된 짧은 정의, 속성/원리/조건을 나눈 행. 중요한 조건을 작은 각주로 내리지 않음 |
| 비교 | 대상별 서술을 흩어 놓지 않고 같은 기준 행에서 정렬. 과도하게 넓은 표는 같은 기준을 유지하며 분할 |
| 곁설명 | 실제 보충이 있을 때만 좁은 보조 열 사용. 없는 경우 본문이 폭을 사용하며 빈 열을 예약하지 않음 |
| 과정·논리 | 2–6개 정도의 읽기 쉬운 단계로 표시하되 내용에 맞춰 분할. 관계 라벨과 방향을 명시. 수치 축 없는 도식을 데이터 그래프처럼 표시하지 않음 |
| 수식·계산 | 목적 → 완전한 식 → 기호/단위/조건 → 대입 과정 → 결과 해석. 조건·분모·예외를 식과 가까이 배치 |
| 시각 자료 | 본문에서 관련 내용을 설명하는 위치에 크롭/표/도식과 해석을 함께 배치. 장식 그림이나 무관한 사진을 추가하지 않음 |
| OX | 번호·명제·O/X를 한 행으로. 별도 답안은 정답+고칠 표현+이유. 모든 OX에 긴 rubric이나 큰 칸을 강제하지 않음 |
| 페이지 | A4 14.3mm 여백을 출발점으로 유지. 러닝 헤더·단원·쪽수, 이어지는 표/자료의 문맥 반복. 임의 6쪽 고정 금지 |

`assets/page-templates.html`·`assets/page-design.css`는 참고만 읽고 새로운 비슷한 CSS를 작성하는 것으로 끝내지 않는다. 각 P지면에서 유지할 배치 관계를 `lib/note-spec.js`의 B템플릿과 조합 규칙에 명시적으로 대응시키고, 같은 합성 콘텐츠로 시안과 제품 PDF를 나란히 비교한다. 모델에는 HTML이나 좌표를 출력시키지 않는다.

한 번에 복잡한 페이지 엔진부터 만들 필요는 없다. 제목 묶음, 짧은 수식 블록, 표 행, 문항 유형, 곁설명 조합부터 바로잡고 실브라우저 인쇄로 확인한다. 기본 인쇄만으로 만족하지 못하는 장문 유형에 한해 높이 측정과 분할 로직을 추가한다.

## 5. 수식·그림의 구체적인 수정 경로

### 수식: 세 문제를 따로 해결

1. **불완전한 원본 크롭:** PDF에 저장된 첫 이미지부터 잘려 있다. `offscreen.js:82`의 cropRegions와 `lib/figures.js:152`의 cropFigure에서 bbox 경계, 분수·첨자의 포함 여부, 원본 픽셀 크기와 표시 크기를 검사한다. 수식 영역 안의 안전 여유만 허용하고 전체 슬라이드 저장으로 우회하지 않는다. 잘린 기존 이미지는 CSS 확대나 생성형 복원으로 고치지 않는다.
2. **수식 배치:** `lib/note-spec.js:211`의 formulaIds를 수식별 figure/행으로 나누고 `lib/note-render.js:70`에 inline/display 문맥을 전달한다. 작은 본문 참조와 독립된 주요 식을 구분한다. 같은 식을 B10 두 개에 다시 풀어서 싣는 대신 개념 홈 위치를 참조한다.
3. **정확성:** LaTeX 문법 통과는 수학 검증이 아니다. 원본과 변수·부호·분모·단위까지 대조하고 확인 실패 시 크롭 또는 확인 필요로 남긴다. 등록 원본 수식을 Writer가 추측해서 재타이핑하게 하지 않는다.

이 PDF의 주된 관찰은 “LaTeX 코드가 그대로 노출됨”이 아니라 **저해상도·잘린 크롭과 인라인 배치**다. 구분자 정규화만으로 해결됐다고 판단하면 안 된다.

### 시각 자료: 세 종류를 구분

- **원본 도표:** 실제 슬라이드의 표·그래프·도식에서 해당 영역만 가져온다. 텍스트 라벨이 없다는 이유로 중요한 비언어 도식이 후보에서 사라지는지 확인한다. 현재는 figure 근거 항목·unit 연결이 없는 후보가 레지스트리에서 제외된다.
- **수치 재조판:** 표/막대/꺾은선은 화면에 확인된 값·단위·축이 있을 때만 다시 그린다. `lib/background-job.js`는 figureData의 ocr를 빈 객체로 넘기고, `lib/figures.js:81`은 OCR 없이는 chart를 허용하지 않는다. 그러므로 현재 이 경로에서는 수치 그래프 재조판이 crop/check로 내려간다. 검증 기준을 삭제하지 말고 실제 크롭 OCR을 연결한다.
- **개념 도식:** 근거 있는 B03/B07의 관계를 트리·흐름도로 그린다. 이는 새로운 통계나 원본 그림 복원이 아니다. 기존 구조화 데이터와 결정적 SVG/HTML로 구현하고, 연결 자체에 근거가 없는 경우 만들지 않는다.

현재 슬라이드당 크롭 상한은 도표 3개·수식 4개다. 무조건 상한을 없애기보다 크기·관련성·중복·품질 기준으로 후보를 고르고, 빠진 필수 자료는 내용 없는 진단 코드로 남긴다. Free의 도표 미탐지와 클라우드 동의 정책은 유지한다.

Markdown은 현재 크롭을 `[수식 이미지]` 같은 텍스트로 대체한다. 이 파일만으로 PDF와 같은 시각 표현을 기대할 수 없다. 이미지가 포함된 별도 내보내기는 저장·내보내기 정책과 함께 따로 정의할 범위다.

웹 보관함은 `landing/vendor/summrizei/`의 사본을 사용한다. lib만 고치지 말고 배포 사본과 테스트를 함께 갱신한다. 프롬프트 변경은 서버 번들, 렌더 변경은 RENDER_VERSION, 계약 변경은 지원 버전·기존 파일 호환성까지 점검한다. 기존 사용자 파일을 새 스키마로 읽을 수 없게 만들지 않는다.

회복 방법도 다르다.

- **표시만 고침:** 저장된 Note를 새 렌더러로 다시 열고 PDF 출력. 모델 재호출 불필요.
- **본문 편집·누락 복구:** 기존 암호화 인식 자료를 메모리에서 열어 해당 생성/검증 단계 재실행. 삭제된 내용은 렌더만으로 돌아오지 않음.
- **잘린 크롭·미인식 도표:** 원본이 메모리에 없으면 사용자가 접근 권한을 가진 강의에서 필요한 구간을 다시 인식해야 함. 평문 원본 저장이나 자동 클라우드 전환으로 해결하지 않음.

## 8. 검증 기록과 아직 남은 확인

- PDF 전체 지면 검토, 수식 페이지 확대, 내장 이미지 크기·잘림 확인.
- 합성 Note로 현재 코드의 문제 3개 재현: B10 원본 수식 두 개가 같은 행의 inline으로 붙음, writing=false의 OX에도 72px 칸 생성, 개념 대상이 실제 이름 대신 C1로 노출.
- 6 Luna가 수식·크롭·도표·Markdown 경로를 읽기 전용으로 독립 검토. 실제 강의 파일이나 암호화 자료는 전달하지 않음.
- 기존 전체 테스트: 1005개 중 통과 1004개, 건너뜀 1개, 실패 0개. 패키징 dry-run 통과. 이는 현 기능 검사이며 지면 품질 합격을 의미하지 않음.
- 실제 PDF에는 최신 코드가 숨기는 수식 고지와 예전 고지 폴백이 남아 있다. 생성/열람 시점의 코드가 현재 로컬 코드와 같다고 가정하지 않는다. 최신 자산으로 재출력해도 위에서 재현한 배치 문제는 별도로 고쳐야 한다.
- 현재 보고서의 수정안은 아직 제품에 적용하지 않았다. 원본 강의 대비 의미 정확성, 낮은 점수의 정당성, 인식되지 않은 원본 그림의 존재 여부, 수정 뒤 브라우저 인쇄 결과는 추가 검증 대상이다.
