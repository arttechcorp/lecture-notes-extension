# 노트 품질 개선 — 기획 반영과 검증 기록

2026-10-06. 기준: [실제 생성 노트 검토](generated-note-audit-2026-10-05.md). 최초 작업은 v1.3.9에서 시작했으며, 재개 시점의 v2.2.0.4 및 origin/main을 통합한 코드에서 최종 확인한다.

## 범위와 책임

Devin은 지면·생성·크롭의 제한된 파일을 별도 작업 트리에서 구현한다. agy/Gemini 3.8 Flash는 읽기 전용으로 검토한다. 이 세션은 원래 기획과 실제 diff를 대조하고, 사본·서버 번들·버전·회귀 검사·브라우저 인쇄를 통합한다. 실제 사용자 강의나 노트 본문을 외부 에이전트, 개발 fixture, 평문 로그에 복제하지 않는다. 검수에는 저장소의 합성 경영·이론 비교·자료 해석 강의를 사용한다.

사용자는 재개하면서 커밋·푸시·main 머지를 승인했다. Supabase는 읽기 전용으로 조회한다. Edge Function 배포, DB 변경, CWS 업로드와 Git 머지는 서로 다른 상태로 기록한다.

## 기존 결과를 고치는 방법

1. **표시:** 기존 Note 파일을 새 렌더러로 다시 열고 PDF 출력. 모델을 다시 부를 필요가 없다.
2. **설명 구조·내용 복구:** 보관함의 암호화 인식 자료로 노트를 다시 생성한다. 렌더러는 이미 삭제된 주장을 되살리지 않는다.
3. **잘린 수식·미인식 도표:** 접근 권한이 있는 원본 강의를 다시 인식해야 한다. 기존 162×31픽셀 크롭의 잘린 분모를 CSS나 생성형 복원으로 회복했다고 판단하지 않는다.

## 적용 한계

- 텍스트가 전혀 없는 다이어그램도 크롭 후보로 보존하고 진단한다. 하지만 현재 Note 레지스트리는 텍스트 근거와 유닛 연결을 요구한다. 이 조건을 충족하지 않는 도식은 자동 본문 삽입을 보장하지 않는다. 무관한 발화나 가짜 근거로 통과시키지 않는다.
- 안전 여백과 저해상도 표시는 잘림을 줄이는 장치이며, 분수·첨자가 모두 포함됐음을 의미적으로 판정하는 비전 검증은 아니다.
- Markdown은 이미지·인쇄 지면과 동등한 출력이 아니다. 기존 이미지 자리표시자 동작을 별도 이미지 내보내기로 바꾸지 않는다.
- P01–P06은 본문·보충·자료·해설의 조합 규칙으로 적용한다. 페이지 수를 고정하지 않으며 러닝 헤더·쪽수와 모든 장문 유형을 보장하는 독립 페이지 엔진은 이번 범위에 추가하지 않는다.
- 합성 입력과 가짜 공급자로 기능을 검사한다. 실제 사용자 강의의 재생성 품질, 실제 Chrome에서 PP-OCR의 숫자 판독 정확도, 운영 모델 응답까지 확인한 것은 아니다.

## 브라우저 검수

- Aside의 실제 Chromium 인쇄로 합성 경영 강의 7쪽과 관계도·음수 막대 그래프 예시 3쪽을 확인했다. 쪽수를 목표로 고정한 것은 아니다.
- 개념 번호·속성 행, 보충 설명, 수식 분수·식 번호·본문 참조, 정정 상자, 비교표, 문항과 해설의 배치를 확인했다. 본문의 `식 {{F1}}`은 `식 식 1`로 중복 표시하지 않는다.
- writing=false에서 답안 칸 0개, 끊어진 내부 링크 0개. 390px 화면의 실제 스크롤 너비도 390px이며 본문은 16px이다.
- 음수 막대는 0선 아래로 표시되고 값 라벨과 항목명 사이 간격을 확보했다. 그래프 예시는 렌더러 검사이며 실제 OCR이 그 숫자를 읽었다는 증거는 아니다.
- 개념과 곁설명 조합·짧은 OX 해설을 묶고, 긴 논증 해설은 루브릭 단위에서 나뉠 수 있다. 모든 장문을 한 쪽에 강제하지 않는다.

## 리뷰의 반영

- OCR 해제 순서를 코드 문자열 검사만으로 확인하던 테스트를 실제 offscreen VM 메시지 검사로 교체했다. 해제가 끝날 때까지 새 BG_RUN은 busy이며, 그 후 BG_DONE 및 다음 작업이 허용된다.
- 초기화에 실패한 OCR 엔진은 현재 작업에서 매번 다시 로드하지 않는다. 작업 해제 후 다음 작업에서 다시 시도한다.
- 랜딩 보관함의 Supabase connect-src를 없애라는 리뷰 의견은 채택하지 않았다. 기존 로그인·보관함 키 기능에 필요한 연결이며 이번 노트 본문 업로드 기능이 아니다.
