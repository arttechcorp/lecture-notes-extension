# 대학 문과·경영 강의를 위한 학습 노트 양식 기획안

버전 1.0 · 2026-10-02 · 상태: PDF 분석에 근거한 설계 제안 / 제품 미적용

목적: 이후 노트 생성 프롬프트, 구조화 출력, 렌더러를 설계할 때 사용하는 공통 명세. 원본 분석은 `source-analysis.md`, 실제 재사용 디자인은 `index.html`과 `assets/`에서 확인한다.

## 1. 최종 방향

**완성된 설명을 읽고, 개념의 관계를 비교하고, 근거를 따라 적용하고, 스스로 꺼내 설명할 수 있는 노트**를 만든다.

LIMIT에서 완성형 개념 설명, 비교 축, 주석, 자료와 해석의 분리를 가져온다. IMFACT에서 단계적 적용, 관계 명제, 단서-해설 대응, 다양한 인출 활동을 가져온다. 대학 강의에 필요한 주장 주체, 조건, 반론, 자료의 위치, 불확실성, 서술형 평가 기준을 더한다.

고정된 18개 섹션을 매번 전부 출력하는 방식이 아니다. **고정된 문서 골격 안에서 18종의 블록을 조건에 맞게 선택한다.** 생성 내용과 시각 배치는 분리한다. 모델은 개념·관계·근거를 채우고, 렌더러가 색상·간격·페이지·정답 공개 여부를 결정한다.

### 검토한 세 접근

| 접근 | 장점 | 문제 | 결정 |
|---|---|---|---|
| 모든 강의에 같은 긴 목차 | 일관성, 구현이 쉬움 | 내용 없는 항목을 채우거나 한 강의를 여러 번 반복하게 됨 | 채택하지 않음 |
| 과목마다 완전히 다른 양식 | 과목 특성에 잘 맞음 | 혼합 강의와 신규 과목에서 규칙이 늘어남 | 과목별 기본 조합에만 사용 |
| 공통 골격 + 내용별 블록 | 일관성과 유연성을 함께 확보 | 선택·생략 기준이 필요 | 권장안 |

### 설계의 적용 범위

문학·역사·철학·사회학·정치학, 경영학·조직행동·마케팅·전략·회계·재무·경제의 대학 강의를 우선 대상으로 한다. 한국어 설명을 기본으로 하되 원어 용어를 함께 보존한다. 강의별 합의가 다른 경우 강의 안의 정의를 우선한다. 이 문서는 완벽한 생성 품질을 보장하는 선언이 아니라, **실패를 판별하고 고칠 수 있는 요구사항**이다.

## 2. 사용자가 노트에서 해야 하는 일

| 사용 상황 | 먼저 보이는 정보 | 필요한 조작/출력 |
|---|---|---|
| 수업 직후 복습 | 강의 질문, 결론, 단원 지도 | 3-5분 안에 배운 범위를 파악 |
| 처음 다시 공부 | 완성형 개념, 쉬운 풀이, 조건, 예 | 단원별 선형 읽기 |
| 유사 개념 구분 | 같은 축의 비교, 공통점, 경계 사례 | 표와 기준별 카드 |
| 논술·토론 준비 | 주장·근거·연결 이유·반론·조건 | 복수 관점과 답안 뼈대 |
| 경영 사례 풀이 | 사실·문제·대안·기준·판단·한계 | 사례와 해석의 분리 |
| 시험 전 점검 | 자기 점검, 숨겨진 해설, 본문 연결 | 답을 먼저 떠올린 뒤 확인 |
| 강의 재확인 | 개념에 연결된 시각/슬라이드/자료 위치 | 정확한 위치, 위치 없음 표시 |
| 태블릿 필기 | 읽히는 본문, 선택한 메모 공간 | 밝은 A4 PDF, 선택 가능한 텍스트 |

## 3. 우선순위와 불변 규칙

규칙 충돌 시 다음 순서로 판정한다.

1. **내용 충실성:** 부정, 수량, 조건, 학자·발화자, 시간적 순서, 단위를 바꾸지 않는다.
2. **근거와 불확실성:** 확인 안 된 사실을 채우지 않는다. 내용이 부족하면 짧고 불완전한 노트를 정직하게 제공한다.
3. **논리의 완결성:** 결론이 왜 나오는지, 어디까지 성립하는지 읽히게 한다.
4. **학습에 맞는 구조:** 내용 유형에 맞는 블록을 고른다.
5. **간결성과 시각적 균형:** 위 조건을 해치지 않는 범위에서 압축한다.

분량이나 디자인을 맞추기 위해 조건을 버리는 것은 금지다. 대학 문과 강의에서 `A는 B이다`와 `이 학자는 조건 C에서 A를 B로 본다`는 다른 주장이다.

**기본 생성 범위는 강의에 근거한 재구성이다.** 강의 밖 사실 보강은 기본적으로 끈다. 교육용 예를 새로 만드는 기능은 별도 선택 사항이며 실제 사례·교수 발언처럼 표시하지 않는다. 이번 에셋의 예시는 모두 양식 검토를 위한 작성 예시다.

## 4. 문서 전체 구성

### 4.1 기본 골격

1. **강의 머리:** 강의명, 수업 주제, 회차/날짜(제공된 경우), 처리 범위.
2. **한눈에:** 중심 질문, 핵심 결론 1-3개, 단원 지도(필요할 때).
3. **단원별 본문:** 단원 질문과 요지 → 개념/구조 → 근거와 적용 → 조건·오해.
4. **연결 정리:** 단원 사이의 관계가 중요한 경우만 종합.
5. **자기 점검:** 답할 근거가 충분한 질문만 선정.
6. **정답·해설:** 닫힌 답 또는 열린 답의 평가 기준, 본문 연결.
7. **확인 필요:** 노트의 신뢰도에 영향을 주는 누락·충돌 목록. 관련 위치에도 짧게 표시.

공지와 메모는 조건부다. 공지는 강의 머리 뒤에, 메모는 학생이 선택한 지면에 둔다. 한 개념뿐인 짧은 강의에는 단원 지도·종합·별도 표를 생략할 수 있다.

### 4.2 시간 순서와 논리 순서

단원은 강의의 처음 등장 순서를 유지한다. 단원 안에서는 정의→근거→적용으로 정리할 수 있다. 멀리 떨어진 단원을 임의로 합쳐 강의의 전개를 바꾸지 않는다. 뒤에서 추가된 조건은 원 개념과 연결하고, 실제 추가된 위치도 보존한다. 교수의 명시적 정정은 최신 설명을 본문에 반영하되 변경 사실을 숨기지 않는다.

연결 지도는 시간 순서와 별개의 요약 보기다. 그래프가 인과인지, 포함인지, 대비인지, 역사적 순서인지 선의 라벨로 구분한다. 자료에 순서만 있을 때 원인 화살표를 그리지 않는다.

### 4.3 표준 단원 골격

`단원 번호·질문·근거 범위 → 한 문장 요지 → 필요한 개념 → 주 관계 구조 1개 → 사례/자료/계산 → 조건·오해 → 다음 단원 연결`

모든 칸이 필수인 것은 아니다. 단원에는 최소한 의미 있는 요지 또는 개념 설명과 근거가 있어야 한다. 유효한 개념이 없는 구간은 공지·질의응답·인식 누락 등 실제 성격대로 처리한다.

## 5. 재사용 블록 18종의 상세 명세

ID는 디자인 에셋, 콘텐츠 계약, 검수 항목에서 공통으로 사용한다. 길이 범위는 첫 버전의 편집 기본값이며 지식의 조건을 자르는 하드 제한이 아니다. 글자 수는 공백 포함 한국어 기준의 대략적인 범위다.

### B01 강의 머리

- **내용:** 강의명, 주제, 제공된 날짜/회차, 처리한 범위, 노트 상태, 짧은 학습 목표.
- **필수:** 제목과 상태. 날짜·교수·학교는 입력에 없으면 만들지 않는다.
- **형태:** 청색 띠, 큰 단원/회차 번호, 어두운 제목. 원본의 러닝 헤더 원리를 사용한다.
- **범위:** 제목 1-2줄, 메타데이터 2줄 이내. 생성일과 강의일은 별도 필드다.
- **금지:** 처리된 일부 구간을 전체 강의처럼 표시, 모델이 추측한 교수 이름.
- **근거:** 메타데이터는 사용자/플랫폼 정보의 출처를 별도로 갖고, 강의 내용 근거와 섞지 않는다.

### B02 한눈에 보는 질문과 결론

- **내용:** 강의가 답하려는 질문 1개와 결론 1-3개. 각 결론은 `결론 1문장 + 이유/조건 1-2문장`.
- **생성 조건:** 결론이 충분히 뒷받침될 때. 탐색적 토론이면 확정 결론 대신 확인된 쟁점으로 표시.
- **형태:** 얇은 색 띠와 연한 바탕, 큰 굵은 결론과 작은 설명의 2층.
- **범위:** 항목당 80-180자 권장. 앞 요약 전체는 첫 지면의 약 1/3 이내를 목표.
- **금지:** 단원 제목을 결론이라고 나열, 조건을 지운 캐치프레이즈, 출제 가능성 추정.

### B03 강의 지도

- **내용:** 3-7개 주요 노드와 관계 라벨. 하위 개념·관점·단원 흐름 중 하나를 표현.
- **생성 조건:** 관계를 그리면 글보다 구조가 분명해지는 경우.
- **형태:** 단순 상자·선, 최대 2단계 위계. 같은 정보의 텍스트 목록 제공.
- **선택 규칙:** 포함 관계는 트리, 절차는 순서, 비교는 표. 관계 종류가 다른 선을 무라벨로 섞지 않는다.
- **분할:** 7개를 넘는 핵심 노드는 상위 지도와 단원별 지도로 나눈다.
- **금지:** 보기 좋게 만들기 위해 근거 없는 연결·인과를 추가.

### B04 단원 헤더

- **내용:** 01 형식 번호, 의미가 드러나는 제목/질문, 1문장 요지, 해당 근거 범위.
- **형태:** 작은 사각 번호 + 제목 + 아래 가는 선. 단계명은 `이해 / 관계 / 적용 / 점검` 중 해당 역할.
- **범위:** 제목 15-40자 권장, 요지 40-100자.
- **페이지 규칙:** 헤더만 페이지 하단에 남기지 않는다. 최소 첫 문단/표의 첫 행과 함께 이동.
- **금지:** 모든 단원 제목을 ‘중요 개념’처럼 일반적인 이름으로 생성.

### B05 개념 설명

- **내용:** 개념명(확인된 원어), 한 줄 정의, 쉬운 풀이, 작동 방식/의미, 범위·조건, 대표 예 중 필요한 항목.
- **최소:** 개념명 + 정의 + 강의 근거. 어려운 새 개념은 정의에만 머물지 않고 설명 문단을 붙인다.
- **범위:** 기본 120-300자, 복잡한 이론은 300-600자까지. 길어지면 독립 주제로 분할.
- **형태:** 정의를 굵게, 설명은 짧은 연결 문장, 슬롯 라벨은 왼쪽 짧은 열.
- **원어:** 첫 등장에만 병기. 같은 한국어 번역을 쓰는 다른 개념은 원어/학자로 구분.
- **금지:** 정의에 이미 사용한 어려운 단어만 순환해서 설명, 강의에 없는 연도·학자 보강.

### B06 공통 축 비교

- **내용:** 대상 2-3개, 동일 기준 3-6개, 공통점, 실제로 구분해 주는 질문.
- **최소:** 같은 비교 기준 하나 이상. 대상에 대해 설명되지 않은 칸은 `강의에서 확인되지 않음`으로 두거나 행 자체를 제거.
- **형태:** 청색 열머리·연회색 기준열. 공통점은 독립 행 또는 표 아래 띠.
- **내용 규칙:** 같은 행의 답은 같은 수준이어야 한다. 한 칸은 정의, 옆 칸은 사례인 표는 금지.
- **긴 내용:** 셀당 1-3문장. 초과하면 개별 설명에 두고 표에는 판별 차이만 남긴다.
- **확장:** 4개 이상 대상은 기준별 연속 카드 또는 두 표로 나눈다. 모바일은 `기준 → A/B/C의 답` 순서로 재배치한다.
- **금지:** 존재하지 않는 대립 구도를 만들기 위해 무조건 A/B를 설정.

### B07 논리 연결

- **내용:** 문제/질문, 전제, 주장, 근거, 근거가 주장을 지지하는 이유, 반론·조건 중 확인된 요소.
- **형태:** 번호가 있는 단계/상자와 라벨 붙은 선. 본문에서는 3-5단계 설명 목록으로도 읽힌다.
- **하위 유형:** 인과, 논증, 과정, 역사적 전개를 `relationType`으로 구분.
- **규칙:** 사실 근거와 규범적 전제를 다른 칸에 둔다. 인과는 작동 경로와 조건을 설명한다. 논증은 전제의 참과 추론의 타당성을 구분한다.
- **부족한 연결:** 강의에서 생략된 추론은 `연결 설명 확인 필요`로 표시. 생략된 근거를 사실처럼 완성하지 않는다.
- **금지:** 상관관계→인과, 시대적 선후→필연적 발전, 학생 의견→교수 결론의 자동 전환.

### B08 사례와 적용

- **내용:** 상황, 확인된 단서, 적용 개념, 단서와 개념의 연결 이유, 판단/대안, 적용 한계.
- **형태:** 연한 황색 `사례` 상자와 연한 보라색 `해석` 상자를 같은 Point 번호로 연결.
- **범위:** 사례 요지 80-180자, 해석 120-300자. 사례 중심 강의는 독립 단원으로 확장.
- **경영 확장:** 의사결정 주체·목표·대안·평가 기준·트레이드오프·추가 필요 자료를 넣는다.
- **출처:** 강의 사례, 자료 사례, 생성 예시를 구분. 새 가상 예시에는 `이해를 위한 가상 예시` 라벨.
- **금지:** 결과가 없는데 실제 성공 사례로 완결, 허구 기업 수치를 실제 통계처럼 표시.

### B09 자료 읽기와 해석

- **내용:** 자료 식별 정보, 짧은 요지, 중요한 단서, 저자/화자의 주장, 교수 해석, 해석의 근거와 한계.
- **형태:** 복숭아색 작은 제목 영역과 흰 자료 영역, 주황색 테두리의 해석 상자.
- **문학:** 서술자와 작가 구분, 표현/시점/형식이 해석을 어떻게 지지하는지 기록.
- **역사:** 생산 시점·주체·목적·관점과 주장하는 사실의 범위를 구분.
- **철학:** 저자의 논제·전제·추론과 교수의 비판을 분리.
- **금지:** 긴 원문 재현, 확인되지 않은 서지정보, 해석 하나를 텍스트의 유일한 의미로 확정.
- **인용:** 꼭 필요한 짧은 구절만 사용하고 원자료 위치를 연결. 글의 대부분은 요지와 분석.

### B10 수식·표·그래프 읽기

- **내용:** 무엇을 구하는지, 식, 기호 뜻/단위, 가정, 강의의 수치, 계산 과정, 결과의 의미와 한계.
- **형태:** 식은 독립 행, 변수는 표, 계산은 단계, 결론은 한 줄 해석.
- **그래프:** 축·단위·기준선·기울기/변화·해석·조건. 수치가 없으면 정성적 그림이라고 표시.
- **검증:** 산술은 코드 검산 대상. 표시 반올림과 내부 계산 정밀도를 분리.
- **분기:** 분모 0, 단위 불일치, 가정 누락, 부호·소수점 인식 충돌 시 계산을 중단하고 확인 필요로 표시.
- **금지:** 표에 없는 숫자를 그래프에 생성, 퍼센트와 퍼센트포인트 혼동, 회계이익과 현금흐름의 무표시 치환.

### B11 헷갈리기 쉬운 점

- **내용:** 흔한 오해 → 정확한 구분 → 조건/반례 → 근거 위치.
- **생성 조건:** 교수가 직접 정정했거나 비교 구조에서 실제로 혼동할 쟁점이 있을 때.
- **형태:** `[주의]` 글자, 적색 가는 선, 옅은 배경. 문장 전체를 붉게 칠하지 않는다.
- **범위:** 단원당 0-2개 권장. 서로 다른 범위를 가진 설명을 억지 모순으로 만들지 않는다.
- **금지:** 강의에 없는 전형적 오개념을 아는 척 추가. 구조상 만든 점검이면 `구분 점검`으로 표시.

### B12 곁설명

- **내용:** 용어 풀이, 짧은 배경, 원어, 앞 단원 연결, 학습 힌트 중 1개.
- **조건:** 없어도 본문의 핵심 의미가 성립해야 한다. 필수 조건·예외는 이곳으로 보내지 않는다.
- **형태:** 왼쪽 좁은 칼럼의 작은 제목과 점선 분리. 디지털 좁은 화면에서는 해당 본문 직후로 이동.
- **범위:** 40-140자, 한 본문 블록에 1개 권장. PDF 9pt 미만 금지.
- **금지:** 뒷받침되지 않는 상식을 메모처럼 넣어 근거 기준을 우회.

### B13 연결 정리 / 핵심 명제

- **내용:** 공통·차이·포함·조건·상호 보완 중 명시적 관계 2-5개.
- **형태:** 황색 얇은 헤더, 옅은 크림 바탕. 명제마다 관계 종류 라벨.
- **목적:** 단원 내용을 또 줄이는 것이 아니라 함께 놓았을 때 드러나는 구조를 정리.
- **규칙:** 본문 정의를 그대로 복사하지 않는다. 관계가 없다면 블록 생략.
- **금지:** `모두 / 항상 / 오직`을 근거 없이 강화, 학파간 논쟁을 화해한 결론으로 만들어 버림.

### B14 자기 점검

- **내용:** 대상 개념 ID, 질문 유형, 질문, 필요한 전제, 난이도/목적, 답안 ID.
- **유형:** 용어 인출, 구분, 사례 적용, 논증/비판, 계산, 자료 해석.
- **형태:** 청록색 단계 띠, 번호와 충분한 응답 여백. 화면은 답안을 닫고 시작.
- **범위:** 기본 4-8개, 짧은 강의 2-4개. 단순 OX만으로 채우지 않는다.
- **규칙:** 하나의 OX에는 하나의 판정 가능한 주장. 조건이 없으면 답이 달라지는 문항은 조건을 추가하거나 열린 질문으로 변경.
- **금지:** 실제 기출·교수 출제라고 표현, 본문에 없는 사실을 알아야만 푸는 질문.

### B15 정답과 해설

- **닫힌 문항:** 정답 + 이유 + 오답이면 올바른 문장 + 복습할 본문 위치.
- **열린 문항:** 유일 정답 대신 필수 논점, 가능한 답안 구조, 허용되는 대안, 누락하면 안 되는 조건.
- **계산:** 과정, 단위, 반올림 기준, 해석. 숫자만 답으로 두지 않는다.
- **형태:** 문항 번호와 연결되는 차분한 테두리 상자. 화면에서 문항별 펼침, PDF는 마지막에 별도 섹션.
- **범위:** 닫힌 문항 50-150자, 열린 문항 3-5개 채점 포인트.
- **금지:** 질문과 해설에 서로 다른 가정, 이견 가능한 논제를 O/X로 확정.

### B16 필기 공간

- **내용:** 빈 공간 또는 `내 말로 설명 / 질문 / 추가 사례`의 짧은 지시.
- **형태:** 연한 점/격자 또는 줄. 격자 5mm, 굵은 경계선 최소화.
- **조건:** 필기형 내보내기에서 선택. 기본 화면은 숨겨 빈 공간 낭비를 막는다.
- **금지:** 생성 모델이 메모칸을 임의 사실로 채움, 필요한 본문을 지우고 메모 여백 확보.

### B17 확인 필요 / 정정

- **내용:** 무엇이 불확실한지, 원인, 영향 범위, 확인할 위치/자료, 확인 전 보류할 판단.
- **상태:** 인식 불확실, 입력 충돌, 처리 누락, 명시적 정정을 구분.
- **형태:** 점선/주의 라벨과 구체 문장. 중요도 강조와 다른 형태.
- **위치:** 영향을 받는 블록 바로 뒤. 심각한 범위 누락은 문서 머리에도 표시.
- **예:** `슬라이드 수치와 발화 수치가 달라 손익분기점 계산을 보류함.`
- **금지:** 모든 곳에 모호한 ‘AI가 틀릴 수 있습니다’만 붙이고 실제 충돌은 숨김.

### B18 수업 공지

- **내용:** 시험 범위, 제출물, 마감, 준비물, 교수의 명시적 요청 중 확인된 내용.
- **형태:** 달력 그림 없이도 읽히는 간결한 표: 항목/내용/기한/근거.
- **기한 규칙:** ‘다음 주’만 들렸고 수업 날짜가 없으면 절대 날짜를 추정하지 않는다. 시간대도 입력에 있을 때만 표시.
- **중요도:** 교수의 시험 언급은 실제 신호로 표시하되 출제 확정이라고 바꾸지 않는다.
- **금지:** 학생 질문을 최종 공지로 취급, 과목의 일반적인 시험 정책 추측.

## 6. 개념을 설명하는 방법

### 6.1 기본 설명 문법

`이 개념은 무엇인가 → 왜 필요한가 → 어떻게 작동/해석되는가 → 어떤 사례에 적용되는가 → 어디까지 말할 수 있는가`

새로운 용어를 정의한 다음 쉬운 말로 한 번 풀어 준다. 쉬운 풀이는 정의를 반복하는 것이 아니라 독자가 이미 아는 상황에 연결한다. 비유를 쓰면 비유가 설명하지 못하는 부분도 짧게 덧붙인다. 모든 개념에 5개 소제목을 출력하지 않고, 의미가 이어지는 2-4문장으로 합칠 수 있다.

### 6.2 내용 유형별 슬롯

| 내용 유형 | 우선 슬롯 | 주 표현 | 빠지면 위험한 정보 |
|---|---|---|---|
| 개념/용어 | 상위 개념·구분 속성·범위·예 | 정의+풀이 | 일반어와 학문어의 차이 |
| 이론/모델 | 질문·전제·분석 수준·기제·설명·한계 | 개념+논리+비교 | 학파·버전·가정 |
| 논증 | 논제·전제·근거·연결 이유·반론·재반론 | 논리 블록 | 누구의 주장인지 |
| 분류 | 분류 기준·하위 범주·겹침·예외 | 트리/표 | 상호 배타성 여부 |
| 역사적 전개 | 시기·행위자·상황·전환·다른 해석 | 타임라인+자료 | 선후와 인과의 구분 |
| 문학/텍스트 | 질문·텍스트 단서·형식·해석·대안 | 자료 해석 | 서술자와 작가 구분 |
| 제도/규칙 | 목적·대상·요건·절차·효과·예외 | 조건표/흐름 | 관할·시점·적용 범위 |
| 경영 프레임 | 목적·분석 단위·축·진단·선택·한계 | 비교+사례 | 도구가 결론을 자동 결정하지 않음 |
| 경영 사례 | 사실·문제·대안·기준·판단·추가 자료 | 사례+대안표 | 알려진 결과와 예상의 차이 |
| 정량 모델 | 변수·단위·가정·식·계산·해석 | 수식+표 | 숫자·부호·기간 |

슬롯에 해당하는 내용이 강의에 없으면 임의로 채우지 않는다. 예를 들어 반론 없는 정의 강의에 반론을 강제하지 않는다. 판단에 필수인 가정이 빠진 경우만 확인 필요를 노출한다.

### 6.3 관계 문법

- **대비:** 같은 기준에서 A와 B의 답이 다름을 적는다.
- **공통:** 공유하는 조건/목적을 적고, 차이가 없다는 뜻으로 확장하지 않는다.
- **포함:** A가 B의 하위 유형인지, 단순 예시인지 구분한다.
- **정도:** ‘더 크다’의 기준·조건·단위를 남긴다.
- **인과:** 원인→경로→결과를 설명한다. 가능한 다른 설명이 강의에 나오면 함께 둔다.
- **논리:** 전제→추론→결론. 앞 명제의 참이 뒤 명제의 참을 보장하는지 범위를 보존한다.
- **시간:** 사건의 순서를 기록한다. 시간적 뒤따름을 원인으로 표기하지 않는다.
- **상호 보완:** 서로 어느 빈칸을 메우는지 설명한다. 이론 전체가 양립한다고 단정하지 않는다.

### 6.4 문장 수준 규칙

한 문단은 한 설명 과제를 맡는다. 연결 이유가 필요한 곳에서는 ‘때문에 / 이 조건에서 / 따라서’의 의미가 실제로 성립하는지 확인한다. 조사만 생략한 명사 나열을 피한다. 강조할 단어는 개념명, 차이를 만드는 말, 조건, 부정어다. 문단 전체를 굵게 처리하지 않는다.

`보통 / 가능하다 / 반드시 / 필요하다 / 충분하다 / 오직 / 모두 / 일부`를 원문 의미보다 강하게 바꾸지 않는다. 교수의 농담·가정·반어·반박 대상은 주장으로 기록하지 않는다. 원어를 모르면 임의로 복원하지 않는다.

### 6.5 바꾸기 전후 예시

아래는 양식 설명을 위한 작성 예시다.

| 부족한 정리 | 개선된 정리 | 개선 이유 |
|---|---|---|
| 인센티브는 성과를 높인다 | 이 모형에서는 보상 기준과 과업 목표가 맞을 때 인센티브가 목표 행동을 유도할 수 있다. 지표가 일부 과업만 측정하면 다른 과업을 소홀히 할 수 있다. | 조건과 한계 보존 |
| 자료 A는 근대화가 좋다고 함 | 자료 A의 발화자는 생활 여건의 변화를 근거로 정책을 긍정한다. 그 경험이 전체 집단을 대표하는지는 자료만으로 판단할 수 없다. | 주장 주체·근거·범위 분리 |
| 손익분기점 200개 | 단위당 공헌이익 5,000원, 고정비 1,000,000원이라는 예시 조건에서 손익분기 판매량은 200개다. 판매량 외 조건이 바뀌면 다시 계산해야 한다. | 단위·가정·해석 포함 |

## 7. 블록 선택과 상황별 대응

### 7.1 선택 순서

먼저 강의의 중심 질문과 유효한 근거 범위를 잡는다. 그다음 내용 단위를 개념·비교·논증·자료·사례·수치·공지로 분류한다. 각 단위에 가장 적합한 주 블록 하나를 선택하고, 필요할 때만 보조 블록을 붙인다. 마지막에 본문에서 답할 수 있는 자기 점검과 해설을 만든다.

**표를 만들 수 있어서 표를 만들지 않는다. 비교 기준이 있을 때 표를 만든다.** 화살표도 연결 의미가 근거에 있을 때만 사용한다. 모델이 스스로 만든 구조의 설득력이 사실의 증거를 대신하지 않는다.

### 7.2 과목별 기본 조합

| 강의 성격 | 기본 조합 | 우선 점검 | 피해야 할 강제 |
|---|---|---|---|
| 사회학 이론 비교 | B05+B06+B08+B13 | 분석 수준·공통점·판별 기준 | 모든 학파를 하나의 정답으로 순위화 |
| 철학·정치사상 | B05+B07+B09 | 발화 주체·전제·반론 | 논쟁적 명제의 OX 확정 |
| 문학 작품 읽기 | B09+B07+B12 | 단서와 해석의 연결 | 줄거리만 요약, 유일 해석 |

## 8. 분량과 반복의 기준

### 8.1 길이 기본값

| 유효 강의 분량 | 단원 | 핵심 개념 | 점검 | A4 참고 범위 |
|---|---|---|---|---|
| 10-20분 | 1-3 | 2-5 | 2-4 | 2-4쪽 |
| 40-60분 | 3-6 | 5-12 | 4-8 | 5-9쪽 |
| 75-100분 | 5-9 | 8-18 | 6-10 | 8-14쪽 |

이는 10.5-11pt 본문과 표/필기 공간을 포함한 **초기 편집 가설**이다. 실제 분량은 발화 밀도, 자료 수, 계산 단계에 따라 달라진다. 페이지 수를 맞추는 것은 정확성보다 우선하지 않는다. 장시간 강의는 단원별 파일/장으로 나눌 수 있다.

### 8.2 유용한 반복과 불필요한 중복

같은 개념이 `앞 결론 / 본문 설명 / 비교 / 점검`에 등장할 수 있다. 역할이 바뀌면 허용한다. 예를 들어 본문은 이유, 표는 차이, 문항은 스스로 꺼내 쓰는 과제를 맡는다. 같은 정의 문장을 세 곳에 복사하는 반복은 줄인다. 정의의 단일 기준 위치는 개념 블록이며 나머지는 개념 ID를 참조한다.

### 8.3 중요도와 강조

중요도는 두 축으로 나눈다. `학습상 핵심`은 개념 체계의 중심성이고, `교수 강조`는 실제 발화 신호다. 시험에 대한 직접 언급은 세 번째 정보로 별도 기록한다. 자주 반복됐다는 이유만으로 시험 출제라고 추정하지 않는다.

한 문단의 강조는 1-2구절, 한 단원의 강한 콜아웃은 1-2개를 기본 목표로 한다. 중요한 조건이 많으면 개수 제한을 지키기 위해 내용을 빼지 말고 단원을 나눈다. 빨강은 주의·충돌, 노랑은 관계 요약으로 의미를 고정한다.

## 9. 시각 디자인 명세

### 9.1 지면의 성격

교재와 유사한 편집감을 유지한다. 청색 제목 띠, 번호 체계, 연한 표머리, 주변 주석, 사례/해설의 색면, 자료 해석의 얇은 테두리, 여유 있는 필기 공간을 사용한다. 원본 로고·캐릭터·특유의 장식·문항 지문은 에셋으로 복제하지 않는다. 첨부 에셋은 이 기능들을 새로 그린 것이다.

### 9.3 타이포그래피

| 요소 | 화면 | A4 PDF | 규칙 |
|---|---|---|---|
| 강의 제목 | 28-34px | 23-27pt | 2줄까지 |
| 단원 제목 | 21-24px | 16-18pt | 번호+제목 |

| 곁설명·출처 | 13-14px / 1.55 | 9pt | 읽을 수 있는 최소 크기 |

화면 기본은 한국어 고딕, 본문 예시의 원자료 요지는 명조를 선택적으로 사용할 수 있다. 한 지면에 서체는 2종 이내. 정확한 글꼴 파일은 배포 허가를 확인한 뒤 제품에 포함한다. 이번 PDF는 설치된 나눔 계열 글꼴을 임베드하고 HTML은 시스템 한국어 글꼴을 사용한다.

### 9.4 그리드와 간격

- A4 210×297mm, 상하좌우 기본 여백 16mm. 전체 본문 폭 178mm.
- 넓은 지면의 곁설명 34mm, 간격 6mm, 본문 138mm. 전체 폭 표는 178mm까지.
- 필기형은 메모 영역을 선택적으로 더한다. 모든 페이지의 20%를 기계적으로 비우지 않는다.
- 간격 기본 단위 4px. 블록 내부 16-20px, 블록 사이 24px, 단원 사이 36-44px.
- 테두리 1px, 색상 띠 3-5px, 모서리 0-8px. 그림자와 과한 카드 장식은 사용하지 않는다.
- 노트 읽기 영역은 넓은 화면에서도 약 900-960px 상한. 한 줄이 지나치게 길어지지 않게 한다.

### 9.5 작은 화면

360px 폭을 기본 검수 대상으로 삼는다. 좌우 16px 여백을 남기고 곁설명은 관련 본문 다음으로 이동한다. 3개 대상 비교는 기준별 세로 묶음으로 변환한다. 행마다 기준을 반복해 대응을 유지한다. 긴 원어·URL은 줄바꿈한다. 차트/수식이 가로로 길면 설명을 유지한 채 별도 확대 보기를 제공할 수 있다. 본문 폰트를 축소해 모든 것을 한 화면에 넣지 않는다.

### 9.6 PDF·인쇄

표의 머리행은 다음 쪽에서 반복한다. 표가 두 쪽 이상이면 `계속`과 표 이름을 붙인다. 한 개념의 정의와 필수 조건, 사례와 대응 해설, 질문과 응답 공간은 가능한 한 함께 배치한다. 큰 블록 전체에 무조건 분할 금지를 적용해 빈 페이지를 만들지 않는다. 긴 블록은 의미 단위로 나누고 제목에 계속 표시한다.

밝은 종이 테마를 기본으로 한다. 웹의 다크 모드를 자동으로 검은 PDF로 출력하지 않는다. 사용자가 별도 선택할 수 있게 한다. 배경 인쇄가 꺼져도 라벨과 테두리로 구조가 유지돼야 한다. 실제 제품 CSS에는 `print-color-adjust: exact`와 현재 인쇄 경로를 함께 검토한다.

### 9.7 접근성과 상호작용

표에는 열/행머리 의미를 부여하고, 도식에는 같은 내용을 담은 텍스트 설명을 둔다. 정답 공개는 키보드로 가능한 네이티브 details/summary를 우선한다. 정답 상태는 색만으로 표시하지 않는다. 읽기 순서는 화면 배치와 일치한다. 200% 확대에서도 내용이 잘리지 않아야 한다. 모션은 노트 이해에 필요하지 않으므로 기본적으로 사용하지 않는다.

## 10. 디자인 에셋 구성과 재사용 방법

| 파일 | 역할 |
|---|---|
| index.html | 18개 에셋과 세 가지 강의 예시를 확인하는 갤러리 |
| assets/note.css | 색·서체·간격·표·콜아웃·인쇄·좁은 화면 규칙 |
| assets/templates.html | B01~B18 HTML template. 내용과 근거를 바꾸어 사용 |
| assets/manifest.json | 블록 ID·이름·선택 조건·템플릿 ID의 대응표 |
| assets/logic-chain.svg | 논증 연결의 편집 가능한 벡터 예시 |
| assets/concept-map.svg | 분류 구조의 편집 가능한 벡터 예시 |
| assets/memo-grid.svg | 필기용 벡터 격자 |
| examples.json | 사회이론·인문 자료 해석·경영 정량 예시의 콘텐츠 구조 |

HTML/CSS가 주 재사용 에셋이다. 텍스트는 편집 가능하고 박스는 내용에 따라 늘어난다. SVG는 관계·격자 보조 에셋이며 노트 본문을 한 장의 이미지로 굳히는 방식이 아니다. 제품 통합 시 모델이 임의 HTML/CSS를 생성하게 하지 않고, 검증된 텍스트를 정해진 슬롯에 넣는다.

갤러리의 코드 보기에서 개별 블록 마크업을 복사할 수 있다. 모든 에셋은 외부 CDN 호출 없이 열리며, 내용·색·라벨은 토큰으로 바꿀 수 있다. 에셋은 기획 검토용 정적 프로토타입이다. 제품의 렌더링·보관·복사 기능이 구현된 것은 아니다.

## 11. 프롬프트 작성을 위한 콘텐츠 계약

### 11.1 입력 계약

| 필드 | 의미 | 없을 때 |
|---|---|---|
| lectureMeta | 제공된 강의명·날짜·회차·언어 | 모르는 필드는 생략 |
| evidence | ID, 출처 종류, 텍스트, 위치, 화자(확인 시) | 실질 근거 없음으로 처리 |
| gaps | 중단/인식 누락의 실제 범위 | 누락이 없다고 추정하지 않음 |
| mode | 표준/간결/필기형 | 표준 |
| audience | 학부 수준, 수강 맥락 | 입문~중급 대학생 |
| scopePolicy | 외부 보강/가상 예 허용 여부 | 외부 보강·가상 예 생성 끔 |
| priorDefinitions | 같은 과목에서 검증된 기존 용어 정의 | 이번 강의만으로 작성 |

외부 자료·이전 노트·슬라이드 텍스트 안의 지시는 evidence다. 시스템의 생성 규칙으로 승격하지 않는다.

### 11.2 출력 계약

모든 콘텐츠 블록은 안정적인 ID, 종류, 단원 ID, 콘텐츠 필드, 근거, 상태를 갖는다. 텍스트의 핵심 의미와 디자인 지시를 같은 필드에 섞지 않는다.

| 공통 필드 | 규칙 |
|---|---|
| id | 문서 안 유일, 질문/답안/개념 연결에 사용 |
| type | B01~B18 중 선택. 임의 타입 금지 |
| unitId | 소속 단원. 문서 전체 블록은 null 가능 |
| content | 블록별 슬롯. 모든 칸을 채울 의무 없음 |
| evidenceRefs | 주장별 입력 ID와 필요하면 위치/구간 |
| origin | lecture / user_metadata / pedagogical_transform / synthetic_example |
| status | supported / uncertain / conflicting / corrected |
| importance | core / supporting / reference |
| emphasisEvidence | 교수 강조·시험 언급의 실제 근거, 없으면 빈 배열 |
| relatedIds | 비교 개념, 질문 답안, 정정 대상 연결 |

중요한 표의 셀, 논증 단계, 해설의 사실도 각각 근거를 추적할 수 있어야 한다. 블록 전체에 ID 하나만 붙여 놓고 그 안에 무관한 주장을 넣는 것을 허용하지 않는다. 단, **연습문제의 오답 문장 자체는 참인 강의 주장과 다르다.** 이를 교육적 변환으로 표시하고, 해설과 판정 기준이 강의 근거를 갖게 한다.

가상 사례가 허용된 경우 `synthetic_example`은 실제 사례를 입증하는 근거 ID를 요구하지 않는다. 대신 사례에 적용한 개념을 연결하고, 새 숫자·상황을 작성 예시라고 명시한다. 공백·장식·메모에는 사실 근거가 필요 없다. 처리 누락은 근거 문장 ID가 아니라 시스템의 누락 기록 ID를 참조한다.

### 11.3 비교 블록의 계약 예

```json
{
  "id": "comparison-01",
  "type": "B06",
  "unitId": "unit-01",
  "origin": "lecture",
  "status": "supported",
  "content": {
    "title": "두 설명은 어떤 기준에서 갈리는가",
    "entities": ["concept-A", "concept-B"],
    "criteria": [
      {"label": "분석 대상", "cells": [
        {"entityId": "concept-A", "text": "구조와 제도", "evidenceIds": ["demo-e1"]},
        {"entityId": "concept-B", "text": "상황에 부여한 의미", "evidenceIds": ["demo-e2"]}
      ]}
    ],
    "common": [],
    "discriminator": "설명의 중심이 제도인가, 행위자의 의미인가?"
  },
  "evidenceRefs": ["demo-e1", "demo-e2"],
  "importance": "core",
  "emphasisEvidence": [],
  "relatedIds": ["concept-A", "concept-B"]
}
```

`demo-*`는 예시용 ID이며 실제 강의 근거가 아니다. 이는 계약 설명용 예이며 현재 제품이 수용하는 실행 스키마가 아니다. 최종 JSON Schema는 프롬프트·검증기·렌더러 변경 시 함께 정의해야 한다.

## 12. 생성·검증 파이프라인 요구사항

### 12.1 단계

1. **근거 정리:** 같은 슬라이드/반복 발화는 중복을 줄이되 새 조건·정정은 보존한다. 숫자·단위·고유명사를 보호한다.
2. **내용 구조 추출:** 중심 질문, 개념 목록, 관계 종류, 강의 순서, 쟁점과 불확실성을 얻는다.
3. **단원과 블록 선택:** 입력 유형에 맞는 주 블록을 고르고 빈 칸을 억지로 채우지 않는다.
4. **설명 작성:** 개념·관계·근거·조건을 쉬운 문장으로 작성한다. 새로운 사실 보강은 기본 금지.
5. **점검과 해설 작성:** 작성된 본문에서 풀 수 있는 문항을 만들고 답안 연결을 검사한다.
6. **내용 검증:** ID, 수치, 화자, 누락, 정정, 논증의 방향, 중요 내용의 반영을 확인한다.
7. **레이아웃:** 검증된 구조를 템플릿에 넣고 화면/PDF/텍스트에 맞게 배치한다.

이는 논리 단계이며 매번 모델을 7번 호출하라는 뜻이 아니다. 초기에는 기존 호출 흐름을 활용하고 코드가 할 수 있는 형식 검사·번호·출처·산술·정답 연결을 모델에 다시 맡기지 않는다.

### 12.2 긴 강의의 합성

청크별 결과를 단순 연결하지 않는다. 원 개념 ID, 등장 시각, 추가 조건, 정정 관계를 보존하며 합성한다. 교수의 뒤늦은 수정이 합성에서 사라지지 않게 한다. 처리된 청크 수와 내용의 충실성은 다른 지표다. `모든 ID가 한 번 인용됨`만으로 충분한 요약이라고 판정하지 않는다.

핵심 개념·조건·사례·공지의 체크리스트를 근거와 대조해 누락을 찾는다. 확인되지 않은 부분을 넣어서 겉보기 완성률을 올리지 않는다. 합성 실패 시 이미 완성된 단원과 실패 범위를 부분 상태로 보여 준다.

### 12.3 프롬프트가 맡을 것 / 코드가 맡을 것

| 모델의 판단 | 코드가 강제 | 사람이 확인 |
|---|---|---|
| 중심 질문·개념·관계·설명 | 타입·ID·필드·참조 무결성 | 핵심 주장과 근거의 의미 일치 |
| 비교 기준·문항·해설 | 숫자 계산·표 차원·답안 연결 | 왜곡된 조건·논쟁의 단순화 |
| 근거 연결 제안 | 허용 ID 확인·위치 변환 | 교수 해석과 학생 발언 구분 |
| 중요도 제안 | 개수·길이 경고·렌더링 | 학습 가치·실제 가독성 |

ID가 존재하는 것은 사실이 맞다는 증명이 아니다. 자동 검사와 의미 검토를 분리한다. 모델이 confidence 숫자를 높게 썼다는 이유로 검증을 통과시키지 않는다.

## 13. 현재 제품과 연결할 때의 변경 범위

2026-10-02 작업 폴더에서 확인한 범위다. 현재 제품에 이 제안이 반영되어 있다는 뜻이 아니다.

| 현재 위치 | 확인한 역할 | 이 기획 적용 시 필요 사항 |
|---|---|---|
| lib/openrouter-client.js | 구조화 출력, 핵심 결론·개념·수식·시각 자료·질문 스키마 | 블록별 콘텐츠 계약과 답안/조건/발화 주체 확장 |
| lib/summary.js | 입력 ID 검증, 항목 정리, 청크 합성, 누락 기록 | 새 필드를 합성·검증 과정에서 보존, 단위/답안 검증 |
| sidepanel.js의 noteText | 강의 시간 순으로 Markdown 조립 | 블록 순서·정답·근거·대체 표현의 결정론적 조립 |
| sandbox.html | Markdown·수식·도식 렌더링과 인쇄 | 블록 표현·접근성·페이지 분할 검토 |
| landing/product-panel.css | 실제 노트와 데모의 공유 스타일 | 새 토큰·표·곁설명, 데모 동기화 |

현재 질문 항목은 질문과 근거 ID를 중심으로 처리되며 답안 필드는 없다. 따라서 프롬프트에 ‘해설을 써라’만 더해도 데이터가 끝까지 보존된다고 볼 수 없다. 새로운 양식은 스키마·검증·합성·표시의 전체 경로가 함께 바뀌어야 한다.

현재 Markdown 호환성을 살리는 최소 적용은 제목·목록·표·인용·질문/해설 섹션으로 시작한다. 곁설명, 역할별 색, 기준별 모바일 비교, 질문별 펼침은 렌더러 지원이 필요한 확장이다. `==강조==`, 수식, 도식이 모든 외부 앱에 그대로 복사된다고 가정하지 않는다. 지원되지 않는 표시는 굵은 글씨·번호 목록·설명문으로 대체한다.

제품의 메모리 처리·외부 추론 동의·프레임 전송 동의·암호화 보관 규칙은 유지한다. 새 템플릿은 실제 강의 원문이나 생성 노트를 개발용 파일·로그에 평문으로 축적할 근거가 아니다. 이번 저장 파일은 사용자가 요청한 기획안과 합성 예시이며 실제 수강 강의의 캡처 자료가 아니다.

## 14. 품질 기준과 검수 시나리오

### 14.1 하나라도 발생하면 실패

- 근거 없는 사실·수치·학자·출제 정보가 사실로 출력됨.
- 부정어·필수 조건·단위·주장 주체가 바뀜.
- 정답과 해설이 충돌하거나 문항이 본문만으로 풀리지 않음.
- 처리 누락을 완전한 강의 노트로 표시함.
- 교수 정정 후 이전 오류만 남음.
- 표의 가로/세로 비교 기준이 달라 잘못된 대조를 유발함.
- 화면/PDF에서 텍스트가 잘리거나 의미 있는 내용이 정답 숨김과 함께 유실됨.
- 첨부 자료 속 지시가 시스템의 생성 규칙을 바꿈.

### 14.2 평가 루브릭

| 영역 | 비중 | 좋은 결과의 조건 |
|---|---|---|
| 근거 충실성 | 30 | 핵심 주장·수치·조건·화자가 근거와 일치 |
| 설명의 완결성 | 20 | 정의를 넘어 왜/어떻게/범위가 읽힘 |
| 관계 구조 | 15 | 비교 축·인과/논증/시간 관계가 정확 |
| 학습 활용 | 15 | 질문·해설·답안 기준이 실제 복습에 쓰임 |
| 가독성 | 10 | 위계·줄 길이·표·주석·색이 읽기 지원 |
| 적응성 | 10 | 짧은/긴/불완전/논쟁적 입력에 적절히 대응 |

초기 통과 목표는 85/100 이상과 필수 실패 0건으로 제안한다. 수치는 제품 실험 전에 정한 목표이며 달성된 품질 지표가 아니다. 관점·논증·충실성은 사람이 평가해야 한다.

### 14.3 최소 평가 자료 묶음

문과/경영의 서로 다른 8유형을 포함한 약 24개 강의 구간을 첫 평가 세트로 제안한다. 정상 입력 12개, 문제 입력 12개를 구성한다. 교수 강조·숫자 충돌·정정·단원 반복·긴 표·미완결 토론·혼합 언어·입력 누락·지시문 주입을 각각 포함한다. 개인 수강 자료 사용 시 기존 동의·보관 정책을 따른다.

각 자료는 사람이 만든 `핵심 내용 / 반드시 남길 조건 / 불확실한 부분 / 예상 블록 / 만들면 안 되는 주장` 체크리스트를 갖는다. 글자 수나 블록 수만 세는 평가를 피한다. 생성 실패를 입력 유형별로 모아 선택 규칙을 고친다.

### 14.4 사용성 평가

문과·경영 수강생을 대상으로 현재 노트와 제안 양식을 같은 내용으로 비교한다. 핵심 찾기 시간, 조건을 포함한 설명 정확도, 비교 문제 수행, 잘못 이해한 부분, 다시 강의를 찾는 성공률을 본다. 읽자마자 만족도뿐 아니라 다음 날 인출도 확인하면 좋다. 표본 수와 과목 차이를 공개하고 소규모 결과를 일반적인 학습 효과로 과장하지 않는다.

### 14.5 렌더링 검수

360·768·1280px, 200% 확대, 컬러/흑백, A4, 긴 표, 긴 원어, 2쪽을 넘는 자료 블록, 정답 펼침/인쇄, 키보드 접근을 검수한다. 실제 Goodnotes/Notability 가져오기는 기기에서 별도 확인한다. 이번 산출물의 로컬 브라우저/PDF 검수는 실제 앱 호환성 검증을 대신하지 않는다.

## 15. 세 가지 완성 예시의 읽는 법

갤러리와 PDF에는 아래 예시를 포함한다. 모두 레이아웃·설명 방법을 보여 주기 위해 새로 작성한 교육용 상황이며 실제 교수 발언이나 검증된 강의 요약이 아니다.

1. **사회이론 비교:** 조직의 규칙 준수를 제도·구조와 상황의 의미라는 두 초점으로 비교한다. 동일한 비교 축, 사례 단서, 서로 다른 해석, 열린 점검을 보여 준다.
2. **인문 자료 해석:** 가상의 도시 정책 자료를 생산 주체·주장·근거·대표성의 한계로 읽는다. 자료 내용과 해석의 구분, 가능한 다른 해석을 보여 준다.
3. **경영 정량 사례:** 고정비 1,000,000원, 가격 12,000원, 단위 변동비 7,000원의 합성 조건에서 공헌이익과 손익분기를 설명한다. 식·단위·가정·검산·의사결정 한계를 보여 준다.

예시의 값과 자료는 일반 강의의 기본값으로 재사용하면 안 된다. 재사용할 것은 슬롯, 질문, 설명 순서와 디자인이다.

## 16. 결정 사항과 다음 단계

**이번 기획의 결정:** 공통 골격+조건부 블록, 완성형 본문, 동일 축 비교, 단서-해석 대응, 사실/해석/관점 분리, 정답과 해설 분리, 근거 중심 생성, 최소 기능의 HTML/CSS 에셋.

**실제 강의 평가로 조정할 값:** 길이별 분량, 문항 개수, 강조 밀도, 단원 크기, 필기 공간의 기본값. 이 값은 프롬프트에 절대 규칙으로 박기 전에 시험해야 한다.

**프롬프트 설계 순서:** 콘텐츠 계약 확정 → 대표 강의 3종으로 블록 선택과 설명 시험 → 스키마/검증/합성 보존 확인 → 실패 시나리오 평가 → 화면/PDF 통합. 이 순서로 진행해야 보기 좋은 예시 하나에만 맞춘 프롬프트가 되는 것을 막을 수 있다.

산출물은 검토 가능한 기획안과 재사용 디자인이며, 최종 생성 프롬프트·제품 코드·서비스 배포는 이번 작업 범위에 포함하지 않았다.
