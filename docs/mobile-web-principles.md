# 모바일 웹 원칙 — Summrizei 랜딩

카카오톡·Instagram 인앱 브라우저를 포함한 모든 모바일 환경에서 페이지가 깨지지 않고 동작하며, 모바일에 맞는 가독성을 갖추기 위한 기준. 구현·검수 시 이 문서를 합격 조건으로 삼는다.

## 0. 목표

"PC 화면을 작게 줄인 페이지"가 아니라, "휴대폰에서도 제품을 이해하고 사전 예약까지 완료할 수 있는 페이지".

데스크톱의 섹션 순서·디자인 시스템은 유지하고, 모바일에서는 **글자 크기·정보 배치·애니메이션·입력창 동작**을 다르게 설계한다.

## 1. 지원 범위

### 정식 검증 환경

| 구분 | 대상 |
|---|---|
| iPhone | Safari, Chrome, 카카오톡 인앱, Instagram 인앱 |
| Android | Chrome, Samsung Internet, 카카오톡 인앱, Instagram 인앱 |
| 태블릿 | iPad Safari, Android Chrome |
| 화면 조건 | 세로·가로, 작은 화면, 분할 화면, 글자 확대 |
| 추가 호환 | 네이버 앱, Firefox Android |

- iOS: 최신 및 직전 2개 주요 버전. Android: 최신 브라우저/WebView.
- 인앱 브라우저는 앱 버전에 따라 달라지므로 검증 시 OS·앱·WebView 버전을 기록한다.
- **UA를 바꾼 Chrome 테스트는 실제 인앱 테스트를 대체하지 못한다.**

### 그 밖의 환경

애니메이션은 단순해져도 **내용 열람·노트 예시 확인·예약 경로는 남아 있어야 한다**.

모바일에서 페이지가 동작하는 것과 Chrome 확장을 설치하는 것은 별개이므로, CTA 주변에 "PC Chrome용 확장 프로그램"임을 명확히 안내한다.

## 2. 가독성 규칙

| 항목 | 기준 |
|---|---|
| 주요 본문·입력창 | 16px 이상, 상대 단위 |
| 보조 설명 | 14px |
| 비핵심 라벨 | 12px 이상 |
| 히어로 제목 | 30~36px 유동 |
| 섹션 제목 | 24~28px |
| 본문 행간 | 1.6~1.75 |
| 좌우 여백 | 16~20px |
| 섹션 간격 | 40~56px로 일관화 |
| 실제 조작 버튼 | 최소 44×44 CSS px, 주요 CTA 높이 48px |
| 인접 조작 간격 | 8px 이상 |
| 일반 텍스트 대비 | 4.5:1 이상 |

- **작은 화면에 맞추려고 글자를 줄이지 않는다.** 줄바꿈하거나 세로로 쌓고, 필요한 경우 펼쳐보기를 제공한다.
- 핀치 줌 허용. 글자 200% 확대에서도 내용·버튼이 사라지지 않아야 한다.
- 고정 높이로 확대된 글자를 잘라내는 방식 금지. 고정 높이가 필요한 영역은 내용이 확대를 따라가도록 재설계한다.
- 목업의 장식용 아이콘에는 실제 버튼과 같은 크기 기준을 강제하지 않되, 사용자가 읽어야 하는 내용은 예외로 두지 않는다.

## 3. 히어로 목업 — 단계별 집중형

캡처 → 요약 → PDF 공유 → 태블릿 필기 이야기는 유지하되, 모바일에서는 장면마다 집중 대상을 바꾼다.

1. **캡처**: 강의 화면과 캡처 상태를 보여준다.
2. **요약**: 강의 영역을 간소화하고 요약 노트를 중심으로 보여준다.
3. **공유**: 현재 장면 안에서 공유 시트를 보여준다.
4. **태블릿**: 문서와 하이라이트를 중심으로 보여준다.

규칙:

- 읽을 수 있는 단계 표시(캡처 → 요약 → PDF → 필기)를 함께 둔다.
- 데스크톱 전체 화면을 축소해 넣지 않는다.
- 장면 전환 시 아래 섹션이 밀리지 않도록 공간을 확보한다.
- 일시정지 버튼은 모든 장면에서 같은 위치.
- **"요약 노트 전체 보기" 등 정적 읽기 경로를 제공한다.** 미리보기에서 잘리는 내용도 접근 가능해야 한다 — 잘리는 것 자체는 가능하나 접근 방법이 없는 크롭은 불합격.
- 정상 전경 재생은 22초 이내 목표 유지(일시정지·백그라운드 제외).
- 모션 감소 설정에서도 시연은 자동 재생한다. 단 필기·펜·전송 링 같은 연출은 그리지 않고 완료 상태로 즉시 스냅하며, 일시정지 버튼은 그대로 동작해야 한다.
- PDF→AirDrop→노트앱은 계속 시각적 시연이다. 실제 파일 전송 기능은 범위 밖.

## 4. 섹션별 규칙

| 섹션 | 모바일 설계 |
|---|---|
| 대학 로고 | 한 줄 목록. 자동 이동 유지 시 터치로 멈출 수 있어야 함 |
| FROM LECTURE TO NOTES | 강의 → 요약 PDF → 노트앱의 세로 흐름. 장식보다 단계 설명 우선 |
| 학생 후기 | 자동 이동 대신 손가락으로 넘기는 카드 목록. 다음 카드 일부가 보여 탐색 가능성 표시 |
| WHY THE SCREEN MATTERS | 강의 자료와 핵심 수치 우선, 두 결과 위아래 비교. 참가자 타일 등 장식 간소화 |
| Pricing | 1열 카드. 예약 CTA와 예시 보기의 위계 구분. 카드 빈 공간 탭으로 모달이 뜨는 동작 제거 |
| FAQ·푸터 | 질문 전체를 터치 영역으로. 작은 링크 밀집 금지, 줄바꿈 허용 |

표·수식처럼 가로 배치가 필요한 콘텐츠만 **해당 영역 안에서 가로 스크롤**을 허용한다. 페이지 전체는 가로로 움직이지 않아야 한다. `overflow-x:clip`만으로는 부족하며 실제 콘텐츠 잘림을 경계 검사로 확인한다.

## 5. 인앱 브라우저 대응

### 예약창과 키보드 — 최우선

- 입력창 글자 16px 이상. 이메일·전화번호에 맞는 입력 모드·자동완성.
- 주소창·하단 도구막대·안전 영역을 고려한 모달 높이(`dvh` + safe-area). `dvh`만으로 모든 문제가 해결된다고 가정하지 않는다 — CSS 우선, 실기기에서 필요할 때만 `VisualViewport` 보정.
- 키보드가 열려도 현재 입력란·오류 안내·제출 버튼에 스크롤로 접근 가능.
- 모달 내부는 스크롤되고 배경 페이지는 움직이지 않는다.
- 닫기 후 원래 스크롤 위치와 포커스 복원.
- 오류는 해당 입력란 옆에 표시하고 첫 오류로 안내.
- 제출 중 중복 탭 방지. 실패 시 입력값 유지. 서버 성공 응답 전 성공 표시 금지.
- 입력값을 URL·분석 이벤트·콘솔에 남기지 않는다.

### 브라우저 제한의 대체 동작

| 상황 | 대응 |
|---|---|
| 클립보드 복사 거부 | 선택 가능한 텍스트 + 수동 복사 안내 |
| 외부 링크·새 창 제한 | 가능한 흐름은 같은 탭의 일반 HTTPS 링크 사용 |
| 외부 브라우저가 필요한 기능 | 사용자 선택으로 안내. 강제 앱 전환 금지 |
| 웹폰트 로딩 실패 | 시스템 폰트로 즉시 읽을 수 있게 유지 |
| 장식용 CDN 차단 | 본문·CTA·예시 기능은 유지 |
| 앱 전환 후 복귀 | 애니메이션 중복 실행 방지, 상태·레이아웃 재확인 |
| 예약 통신 실패 | 명확한 실패 상태와 재시도 제공 |

인앱 브라우저 감지는 안내를 위한 보조 수단으로만 사용한다. UA 문자열로 기능 지원을 단정하거나 접근을 막지 않는다.

## 6. 검증

### 자동 검증

- 화면 폭: **320 / 360 / 375 / 390 / 430 / 600 / 768 / 820 / 1024px**, 760px 분기점 전후와 짧은 가로 화면.
- Chromium·WebKit 모두.
- 모든 히어로 단계에서 콘텐츠 경계·필기 좌표 확인.
- 일반 모션·모션 감소 모두 확인.
- 폰트/CDN 차단, 느린 통신, 예약 실패 응답.
- 예약 열기 → 입력 오류 → 재시도 → 성공 표시 → 닫기.
- 예시 모달, 표 스크롤, FAQ, 학생 요금 토글.
- 중요 요소의 **실제 경계 검사**. `scrollWidth`만으로 합격 처리하지 않는다.
- 예약 성공 테스트는 모의 응답으로 수행. 실제 예약 데이터 무단 생성 금지.

### 실기기 검증(출시 전)

iPhone·Android 각각에서 카카오톡·Instagram으로 배포된 HTTPS 링크를 직접 연다: 첫 화면에서 핵심 설명과 예약 버튼 확인 / 스크롤하며 주소창 접힘·펼침 / 히어로 전체 루프와 일시정지 / 노트 예시 열기·읽기·닫기 / 이메일·전화번호 입력과 키보드 전환 / 오류 안내·제출 버튼 접근 / 뒤로가기·앱 전환 복귀·화면 회전 / 큰 글자·VoiceOver·TalkBack 기본 탐색.

### 합격 기준

- 페이지 전체 가로 스크롤 없음.
- 설명·가격·CTA·오류 메시지의 잘림·겹침 없음.
- 확대 없이 주요 내용을 읽을 수 있음.
- 키보드가 올라와도 예약 완료 가능.
- 자동 이동 콘텐츠를 멈추거나 직접 읽을 수 있음.
- 모든 필수 기능에 성공·실패·대체 경로가 있음.
- 장식 기능 실패가 예약과 콘텐츠 열람을 막지 않음.
- 지정한 실제 인앱 브라우저 조합에서 중대 오류 0건.
