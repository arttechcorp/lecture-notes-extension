# 수식·단순 그래프 복원 평가 기준 v1

합의일: 2026-10-02. 목표는 **의미는 동일하고, 시각적 표현은 달라진 복원**이다. 이번 산출물은 평가 기반이며 복원 모델의 성능 측정 결과가 아니다.

## 판정 순서

1. 입력 파일·체크섬·출처·정답 주석을 확인한다. 원본 미검토 또는 파일 불일치는 유효한 평가 실행이 아니다.
2. 각 원본 영역과 출력 영역의 대응을 확인한다. 그림 없는 본문에 그림을 추가하면 실패한다.
3. 아래 핵심 내용 체크를 모두 확인한다. 하나라도 명확한 오류가 있으면 실패한다.
4. 핵심 내용에 오류가 없어도 확인하지 못한 항목이 있으면 보류한다.
5. 내용이 맞는 결과에만 디자인 차이를 적용한다. 눈에 띄는 재디자인이면 통과, 시각적으로 동일하거나 압축·해상도만 바꾸었으면 실패한다.

실패는 보류보다 우선한다. 예를 들어 분모가 틀리고 색상 차이는 아직 검토하지 않았다면 실패다. 판독 불가 원본에서 출력을 보류한 것은 안전한 동작이지만 복원 성공으로 세지 않는다. 그림 없음 정답에서 아무 그림도 만들지 않는 것은 통과이며 디자인 변경은 해당하지 않는다.

## 필수 체크

| 항목 | 보존할 내용 | 허용되는 변경 |
|---|---|---|
| 텍스트 | 핵심 라벨·숫자·단위·부호·대소문자 | 의미가 같은 줄바꿈, 서체, 위치 |
| 구성 요소 | 계열·곡선·막대·의미 있는 도형·수식 수 | 배경·장식 제거. 축·격자 선을 데이터 계열로 세지 않음 |
| 관계 | 연결, 화살표 방향, 포함, 범례와 계열 대응 | 관계를 유지한 배치 변경 |
| 수식 | 변수, 연산자, 첨자, 괄호 범위, 분수/근호 범위, 조건 | 수학적으로 동등한 표기. 단순 문자열 비교는 동등성 증명이 아님 |
| 그래프 | 축, 단위, 척도, 범위, 추세, 극값, 교점, 불연속 | 내용이 보존되는 크기·종횡비·색·선 스타일 변경 |
| 근거 | 원본에 실제로 보이는 요소만 복원 | 읽히지 않는 요소의 명시적 보류 |
| 영역 대응 | 원본 regionId와 복원 영역, 복수 그림의 구별 | 그림 전체의 페이지 배치 변경 |

색이 계열을 구분하는 원본이라면 색을 바꾸어도 대응을 유지해야 한다. 위/아래·안/밖이 의미인 경우 위치를 마음대로 바꿀 수 없다. 추세가 비슷해도 로그 축을 선형 축으로 바꾸면 실패한다. 음성이나 주변 설명으로 추측한 도형은 화면 복원의 정답으로 인정하지 않는다.

## 수치와 위치 허용 오차

- 원본에 직접 적힌 값·단위·수식 기호: 정확히 보존한다. `1`, `1.0` 같은 표기 변경은 값뿐 아니라 유효숫자 의미도 검토한다.
- 픽셀로만 읽는 그래프 값: 사례별로 허용 오차를 기록한다. 기본 실험값은 표시된 축 범위의 2%이며, 실제 원본 해상도·선 두께에 비해 지나치게 엄격/느슨하면 사례별 값을 우선한다. 단위·축 해석이 틀린 결과를 오차 안이라고 통과시키지 않는다.
- 숫자가 없는 개념 곡선: 수치 오차 대신 곡선 수·증감 구간·교차·연속성 같은 관측 가능한 특성으로 평가한다. 소스 파일의 수식이나 파일명에서만 알 수 있는 값을 이미지 정답으로 추가하지 않는다.
- 입력 영역 bbox는 정규화 `[x,y,w,h]`다. 여백 포함 범위를 허용하되, 복수 그림을 한 영역으로 섞거나 핵심 요소를 누락하면 실패한다. 디자인 자유 때문에 출력의 절대 좌표를 입력 좌표와 같게 요구하지 않는다.

## 디자인 차이

글꼴·색·선·여백·의미와 무관한 배치 중 하나 이상에 사람이 식별할 수 있는 변화가 있으면 된다. 큰 차이를 만들기 위해 내용을 바꾸지 않는다. 동일 바이트는 자동 실패다. 다른 인코딩·파일 형식·메타데이터·해상도·압축 잡음으로 바뀐 시각적 복사본도 검토에서 실패시킨다. 해시가 다르다는 사실만으로 재디자인을 인정하지 않는다.

## 정답과 검토 기록

`eval/visual/manifest.json`은 출처, 이미지 경로와 SHA-256, 사례 그룹/분할, 영역별 정답 체크리스트를 가진다. 정답 작성 시 실제 렌더링 이미지를 확인하며, 외부 페이지 설명만 본 것은 `pending`이다. `reviewed`에는 검토자 식별자를 기록한다. 이번 초기 주석의 AI 시각 검토는 사람의 독립 정답 검증을 대신하지 않는다. 배포 평가 전에 도메인 검토자가 확인한다.

검토 결과에는 runId, reviewer, 출력 파일, 항목별 pass/fail/unknown, design 판정, 오류 설명을 기록한다. 입력의 정답 주석을 복원 모델에게 넘기지 않는다. 평가 CLI는 검토 결과를 집계하며 이미지를 이해하거나 수학적 동등성을 자동 증명하지 않는다. 복원 모델이 작성한 자기평가만으로 통과시킬 수 없다.

## 지표

- 전체 pass/fail/hold/missing 건수. missing은 hold에 포함하고 따로 표시한다.
- 양성 복원 성공률 = 통과한 양성 / 전체 양성.
- 양성 시도 정확도 = 통과한 양성 / 출력한 양성. 시도가 0이면 100% 대신 null.
- 양성 보류 동작 비율과 전체 보류율. 오답을 많이 보류해서 정확도만 높아지는 것을 구분한다.
- 음성 오생성률 = 그림을 출력한 음성 / 전체 음성. 미실행 음성이 있으면 커버리지가 불완전하므로 낮은 오생성률을 성능으로 해석하지 않는다.
- 검토 커버리지 및 주석 커버리지. 수식·그래프·음성을 따로 보고한다.

최초 소규모 코퍼스는 smoke/dev 용도다. `holdout` 표시는 추후 실행 분리를 위한 것이며 이미 개발자가 확인한 초기 자료는 블라인드 검증셋이 아니다. 원본/흐림/크롭/재디자인 파생물은 같은 group과 split에 둔다. 향후 강의/작성자 단위로 새 자료를 분리하여 확대해야 한다. 이 자료만으로 99% 정확도나 제품 준비 완료를 주장하지 않는다.

## 이번 범위에서 제외

실제 강의 캡처, 개인정보, 모델 학습, 외부 이미지 추론, 제품 프롬프트 변경은 포함하지 않는다. 공개 자료의 검색·다운로드만 Exa와 원 출처를 사용한다. 키는 요청 헤더에만 사용하고 결과·로그·코퍼스에 넣지 않는다. CC BY-SA 자료와 파생물에는 저작자·라이선스·변경 내용을 유지한다.
