# 시각 복원 평가 기반 — 2026-10-02

## 승인된 범위

공개 수식·단순 그래프 이미지를 수집하고, 의미 보존과 시각적 재디자인을 독립적으로 평가하는 작은 오프라인 평가 기반을 만든다. 실제 강의 캡처 저장, 제품 인식 경로 변경, 모델 추론·학습은 이번 범위가 아니다. 사용자는 Exa 검색 API 사용과 공개 평가 이미지 다운로드를 승인했다. 키는 기존 비공개 파일에서만 읽는다.

## 평가 계약

- 핵심 텍스트, 숫자, 단위, 부호, 의미 있는 구성 요소 수를 보존한다.
- 연결·화살표 방향·포함·대응 관계를 보존한다. 장식은 개수에서 제외한다.
- 수식은 변수·연산자·첨자·분수 범위·조건을 보존한다. 수학적 동등성은 별도 검토하며 문자열 유사도로 대체하지 않는다.
- 그래프는 축·단위·선형/로그 척도·계열 수·범례·증감·극값·교점·불연속을 보존한다. 명시 수치는 정확히, 픽셀에서 추정하는 좌표는 사례별 허용 오차로 평가한다. 숫자 없는 개념도에 수치를 만들어 넣지 않는다.
- 실제 원본 영역에 없는 요소를 추가하지 않는다. 영역 및 결과의 대응을 확인한다. 불확실하면 보류한다.
- 디자인은 자유이나 의미는 보존해야 한다. 원본과 시각적으로 동일하면 실패한다. 압축·해상도만 변경한 것도 재디자인으로 인정하지 않는다. 글꼴·색·선·여백·의미와 무관한 배치의 눈에 띄는 변화는 허용한다.
- 핵심 오류는 디자인 점수로 상쇄할 수 없다. pass/fail/hold를 구분한다. 미실행 사례는 hold로 세되 미실행 건수도 별도 보고한다. 그림 없음 정답에 아무것도 만들지 않은 것은 pass이며 재디자인 조건은 해당하지 않는다.
- 정확도와 성공률, 보류율, 음성(그림 없음) 사례 오생성률을 함께 보고한다. 작은 초기 코퍼스는 배포 성능·99% 정확도를 입증하지 못한다.

## 작업 순서

1. LUNA: 출처·라이선스·이미지 후보 조사. 원본 픽셀을 확인하기 전 정답을 확정하지 않는다.
2. SOL: 표준 Node.js 기반 Exa 검색/수집 보조 도구, 평가 CLI와 최소 회귀 검사. 별도 의존성을 추가하지 않는다.
3. 조율자: 원본 시각 확인, 사례별 정답과 허용 오차 작성, 출처 확인, 평가 기준 문서화.
4. SOL: 필요한 자체 제작 대조 이미지·미리보기 생성 및 코퍼스 통합. 수집 원본과 파생 이미지는 구분한다.
5. 독립 검토 및 전체 회귀 검사. 결과를 모델 성능으로 오인하지 않게 기록한다.

## 산출물

`eval/visual/`에 출처·체크섬·정답을 갖는 manifest와 공개 이미지, 검토용 미리보기, 판정 예시를 둔다. `tools/visual-eval.mjs`는 manifest 확인과 검토 판정 집계를 제공한다. `tools/visual-eval.test.mjs`는 그대로 복사·의미 오류·보류·음성 사례를 검사한다. Exa API 키는 이 경로들에 복사하지 않는다.

## 작업 결정

- 기존 `b/dev` 작업 폴더 `.worktrees/dev_ANTI`를 재사용한다. 현재 주 작업 폴더의 `b/note-design`은 변경하지 않는다.
- 공개 평가 자료 저장은 사용자의 명시적 요청이며 제품의 강의 입력 저장 금지와 구별한다.
- 모델이 주장하는 자기 정확도 대신 사람이/검토자가 원본과 결과를 비교해 남긴 항목별 판정을 집계한다. 픽셀 유사도만으로 의미 보존을 자동 판정하지 않는다.
- 이번에는 커밋·푸시 없이 검토 가능한 파일로 전달한다.
