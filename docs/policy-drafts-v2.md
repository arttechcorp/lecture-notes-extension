# 정책 문서 초안 v2 (검토용)

> **상태**: 초안 · 미공개 · **법률 검토 전** — 이 문서는 법률 자문이 아니며, 게시 전에 반드시 법률 검토를 거쳐야 합니다.
> **적용 시점**: v2 기능 출시 시. 신규 시행일은 **(미정)**이고, 현행 문서의 시행일은 2026.09.19입니다.
> **작성 근거**: `docs/architecture-v2.md`(이하 계획서), `AGENTS.md` §2 불변식, 현행 `landing/policies/*.html`, `CHROMEWEBSTORE.md`, `manifest.json`, `server/index.js`.
>
> 태그 읽는 법:
> - **[현행]** — 지금 배포된 코드와 페이지에 이미 해당하는 내용입니다.
> - **[v2 출시 시]** — v2 기능이 출시되어야 성립하는 내용입니다.
> - **[후보]** — 아직 채택되지 않은 공급자·방안입니다.
> - **⚠️ 확인 필요** — 소스 문서에 값이 없어 게시 전 확인이 필요한 항목입니다. 괄호 안에 확인 주체를 적었습니다.
>
> 법조 인용은 개인정보 보호법 제26조(업무위탁)·제28조의8(국외 이전)·제30조(처리방침)와 저작권법 제104조의2(기술적 보호조치)만 사용하며, 조문은 모두 법률 검토에서 확인합니다.
>
> 이 문서는 제안일 뿐이며 `landing/policies/*.html`과 `CHROMEWEBSTORE.md`는 수정하지 않았습니다.

## 0. 결정이 필요한 항목 (사용자 확인)

1. **Supabase 리전** — 계획서 9는 서울을 "권장"하지만 미확정입니다. 서울이면 국외 이전 고지 범위가 줄어듭니다. 지금 쓰는 프로젝트(`rppknkhbiivyurhvljoi`)는 시드니(ap-southeast-2)에 있어, 서울로 옮기려면 새 프로젝트가 필요합니다(2026-10-03 CLI로 확인). → §2.3 표, §2.3 고지 방식.
2. **서버 호스팅 사업자·리전** — 컨테이너 런타임(Cloud Run 서울, Fly.io 등)이 후보이고 미정입니다(계획서 11). 수탁자 행과 소재 국가가 여기에 달립니다. → §2.3.
3. **클라우드 STT 공급자** — 결정됨(2026-10-03): OpenRouter를 거친 Microsoft MAI-Transcribe 2(Azure). 서버 라우트 `POST /v1/stt`는 아직 Groq 직접 호출 구현이라 바꿔야 합니다. 남은 확인은 실제 처리 리전과 보존 조건입니다. → §2.1, §2.3.
4. **Jev 채택과 무보존 계약** — 운영사는 TypeSafe입니다(계획서 9·22). 무보존은 기업 계약이 필요합니다(계획서 10.3). 미채택 시 같은 `/v1/judge` 뒤에서 gpt-4.1-nano 로그확률 판정으로 대체합니다. → §2.3.
5. **국외 이전 고지 방식** — 별도 동의 절차를 둘지, 처리방침 공개로 갈음할지 정해야 합니다(개인정보 보호법 제28조의8, 조문은 법률 검토에서 확인). → §2.3 구조, §2.4.
6. **호스트명 저장의 스토어 분류** — `usage_events`가 호스트명만 저장합니다(계획서 12). 이것이 스토어 폼의 "웹 기록"에 해당하는지 확인이 필요합니다. → §5.
7. **계정 도입과 이용 연령** — 구글 로그인이 도입되면 현행 약관의 "계정 불필요" 문장이 사라지고, 만 14세 기준을 계정 체계에서도 유지할지 정해야 합니다. → §1, §2.2.
8. **usage_events 비식별화 문구** — 계정 삭제 시 `user_id`를 제거하고 집계만 남깁니다(계획서 9·12). 게시 문구로의 표현을 확정해야 합니다. → §2.5.
9. **운영자·개인정보 담당 표기** — 현행 "운영자 wab · 이기욱 / 개인정보 담당 부지환"의 유지 여부. → 문서 전반의 머리말.
10. **설치 경고 권한의 `optional_permissions` 이전** — 패키징 단계에서 확인 예정이며 결과가 없습니다(계획서 17). → §4.
11. **요금제 수치** — Free 월 한도와 유료 요금이 미정입니다(계획서 22). 약관·스토어 문구에 수치가 필요하면 먼저 결정해야 합니다. → §1(terms), §5.
12. **온디바이스 요약(Gemini Nano) 존속** — 현행 방침은 기기 내 요약 경로를 명시하지만, 계획서의 계획·작성 단계는 서버 LLM만 기술합니다. 유지·폐지 여부를 확인해야 합니다. → §1, §2.1.
13. **법률 검토 일정** — 출시 전 법률 검토가 필요합니다(계획서 22). → 문서 전체.

### 2.5 이용자의 권리와 삭제

- 열람·정정·삭제·처리정지와 동의 철회는 개인정보 담당 이메일(summrizei.support@gmail.com)로 요청할 수 있으며, 신청 이메일 주소로 본인 확인 후 처리합니다(현행 절차 유지).
- 기기 내 전체 삭제는 기기 키 폐기(crypto-shredding)로 이뤄져 즉시 복호화가 불가능해집니다(계획서 9).
- 서버 보관함 삭제는 암호문 객체를 삭제합니다. 계정 삭제 시 프로필·보관함·피드백을 삭제하고, `usage_events`는 `user_id`를 제거한 뒤 집계만 남깁니다(계획서 9·12, 비식별화 문구는 §0-8).
- 진단 파일은 이용자가 직접 보낼 때만 존재하며, 처리 단계·시간·오류 코드만 담고 처리 후 삭제합니다(계획서 13).
- 설정·동의 기록과 로컬 로그는 설정 화면에서 이용자가 직접 삭제할 수 있습니다.

### 2.6 안전성 확보 조치와 한계

- 파생물은 AES-256-GCM으로 레코드마다 암호화합니다(96bit 무작위 IV, AAD = `{store, recordId, schemaVersion}`로 레코드 바꿔치기 방지). 기기 키는 추출 불가능한 `CryptoKey`로 IndexedDB에 둡니다(계획서 9).
- **한계**: 같은 브라우저 프로필에서 확장 코드를 실행할 수 있는 공격자는 막지 못합니다. 계획서가 명시한 한계이며 방침에도 그대로 기재합니다.
- 외부 통신은 HTTPS만 허용합니다. 서버는 요청 본문과 인증 헤더를 기록하지 않고 라우트·상태·소요시간·바이트·모델·코드만 기록합니다(계획서 9·11).
- 서버는 STT 요청의 오디오를 원장·로그·오류 본문에 남기지 않고 요청 식별용 해시만 씁니다(근거: `server/index.js` stt()).
- 공급자 업로드 전에 알려진 워터마크·학번 영역을 마스킹합니다(계획서 6.3).
- 보호조치(EME/DRM, 암호화 HLS `EXT-X-KEY`·`EXT-X-SESSION-KEY`, DASH `ContentProtection`)가 감지되면 작업을 중단하며 우회하지 않습니다 — 저작권법 제104조의2(기술적 보호조치)가 계획서의 근거입니다(조문은 법률 검토에서 확인). 이 경우 실시간 모드를 제안만 하고 자동 전환하지 않습니다.
- Referer 헤더 규칙은 이용자가 보던 페이지의 Referer를 재현하는 범위로만, 확장 자체의 미디어 요청에 한정해 적용하고 작업 종료 시 제거합니다(계획서 6.1).
- 네트워크 예의: 호스트당 동시 수신 4 이하, 처리량 상한, 429·5xx 지수 백오프와 `Retry-After` 준수(계획서 6.1).
- YouTube는 백그라운드 모드 대상에서 제외하고 실시간 모드만 제공합니다(계획서 19).
- 원본 미디어 내보내기 기능은 존재하지 않습니다(계획서 6.1, D8).
- 인식 엔진(클라우드/로컬)과 소스(백그라운드/실시간)를 조용히 바꾸지 않고, 멈춰서 이용자에게 묻습니다(AGENTS.md §2).

| `declarativeNetRequestWithHostAccess` | permissions | Referer를 요구하는 미디어 CDN에 한해, 사용자가 보고 있던 페이지의 Referer를 재현하는 임시 세션 규칙을 걸고 작업 종료 시 제거합니다. 다른 출처로 위장하거나 광고·트래커 차단·임의 헤더 조작에는 사용하지 않습니다. *(Sets a temporary session rule reproducing the viewed page's Referer for the media CDN only, removed after the job. Not used to spoof other origins or modify arbitrary headers.)* |
| `identity` | permissions | Supabase 계정의 구글 로그인(`chrome.identity.launchWebAuthFlow`)에 사용합니다. 로그인 결과(인증 토큰·계정 식별자·이메일) 외에 Chrome 프로필의 신원 정보를 읽지 않습니다. 요청하는 OAuth 범위는 구현 시 확정 ⚠️ 확인 필요. *(Used for Google sign-in via launchWebAuthFlow. Does not read Chrome profile identity beyond the sign-in result (auth token, account identifier, e-mail); the OAuth scopes to request are settled at implementation — ⚠️ 확인 필요.)* |
| `power` | permissions | 사용자가 시작한 백그라운드 작업이 진행되는 동안만 `chrome.power.requestKeepAwake("system")`으로 유휴 절전을 막습니다. 상시 절전 방지나 화면 켜짐 유지에는 사용하지 않습니다. *(Prevents system idle sleep only while a user-started background job runs. Not used for display keep-awake or persistent wake locks.)* |
| `unlimitedStorage` | permissions | 강의당 약 4MB(추정)로 암호화된 강의 패키지가 브라우저 스토리지 축출로 삭제되지 않게 합니다. 원본 영상·음성은 저장하지 않습니다. *(Keeps encrypted lecture packages (est. ~4MB per lecture) from browser storage eviction. No raw media is stored.)* |
| `https://openrouter.ai/*` 제거 | host_permissions | 사용자 API 키 직접 호출(BYOK) 경로를 삭제해 이 호스트 권한이 불필요해집니다. 요약 호출은 운영 서비스 경유만 사용합니다. *(Removed: the BYOK direct-call path is retired; summarization goes through the operator service only.)* |

- `<all_urls>`는 유지합니다. 사유는 현행과 같습니다 — 임의의 강의 페이지에서 사용자가 시작한 캡처·소스 식별에 필요합니다.
- **설치 경고·`optional_permissions` 검토**: 계획서 17은 설치 경고를 일으키는 권한을 `optional_permissions`로 옮길 수 있는지 패키징 단계에서 확인하라고 하며 결과가 없습니다 → ⚠️ 확인 필요(구현 시). Chrome이 실제로 보여주는 설치 경고 문구는 여기서 단정하지 않습니다.
