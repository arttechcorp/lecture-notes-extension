## 지금까지 한 일

### 1. 2단계 재검토 (커밋 `bad8498`, `2233f69`)

- 2단계 테스트는 제품 경로와 다른 근거 모양을 썼다. 제품에서는 화면 한 장의 OCR이 한 줄로 합쳐진다. 실제 경로에서 수식 복원은 0/6이었고, 여러 줄 수식 보류 보장도 깨져 있었다.
- 그림 속 글자를 그대로 옮기면 OCR 오독(`x = 12`처럼 분수를 잘못 읽은 것)이 "근거 있음"으로 통과한다.
- 정상 문장을 오탐한다. 제목이 `Graph theory`로 시작하면 요약 전체가 실패한다. `|x|`, `Pie chart`, `$5…$10` 같은 표현은 항목이 탈락한다. 2단계 이전에 만든 보관 노트는 수식이 든 항목이 빠지거나 아예 열리지 않을 수 있다.
- 실제 강의 화면 3장(수식, 그래프, 소자 그림, 빨간 판서)으로 확인했다. OCR만으로는 일반 텍스트, 수식, 그림 라벨, 손글씨를 구분할 수 없고, 손글씨는 거의 읽히지 않으며, 판서가 덮은 인쇄 문장은 사라졌다.
- 도구: `tools/visual-flow-check.cjs`, `tools/visual-ocr-replay.mjs`, `tools/visual-region-probe.mjs`(픽셀 기반 텍스트·그림·손글씨 영역 시제품, 3장에서 OCR 줄 분류 52/57)

### 2. 시간축 판서 분리 시제품 (커밋 `82f7811`)

- 아이디어(사용자 제안): 판서는 깨끗한 슬라이드 위에 시간에 따라 쌓인다. 그래서 슬라이드 첫 화면과 비교해 달라진 부분만 판서로 본다.
- 합성 시퀀스 결과: 판서 정밀도 .91, 재현율 .99. 판서가 덮인 화면 전체를 OCR하면 인쇄 글자 유사도가 0.47까지 떨어진다.
- 사용자와 합의한 결정:
  - 펜 커서는 따로 찾지 않는다.
  - 같은 슬라이드에 나중에 생긴 것은 애니메이션까지 모두 판서로 본다.
  - 검은 잉크가 검은 글자 위에 겹치는 문제는 우선순위가 낮다.
- 도구: `tools/visual-ink-layer-probe.mjs`

### 3. 슬라이드 전환 판정 수정, 비전 모드 복구 (커밋 `7565108`)

- 기존 규칙(화면의 32% 이상 변화)은 실제 흰 배경 슬라이드 전환을 하나도 잡지 못했다(변화 0.06~0.31). 그래서 슬라이드 번호가 늘지 않았고, 비전 모드는 첫 장 이후 화면을 보내지 않았다.
- 새 규칙(사용자 지시): 슬라이드 첫 화면의 내용 중 20% 넘게 배경으로 돌아가면 새 슬라이드다. 판서를 더하거나 지우는 것은 전환이 아니다.
  - 거의 빈 화면에서는 내용이 나타나는 것을 전환으로 본다.
  - 일시정지 후 재개하면 새 슬라이드로 시작한다.
- 실제 화면 재생(판서 추가 → 지움 → 전환, 실제 강의 화면 3장, 흰 화면 → 슬라이드)에서 OCR·비전 두 모드 모두 기대와 일치했다.

### 4. 판서 층 제품 통합 (커밋 `67bce8b`)

- OCR 모드:
  - 새 슬라이드의 첫 화면은 통째로 OCR하고, 그 화면을 메모리에만 기준으로 둔다.
  - 같은 슬라이드를 다시 캡처하면 `lib/ink-layer.js`가 달라진 부분만 남긴 이미지를 OCR하고, 근거 앞에 `(판서) `를 붙인다.
- 요약 프롬프트는 `(판서)` 근거를 강조·주석으로만 쓰게 했다. 수식 근거로도 쓰지 않는다.
- 비전 모드는 바뀌지 않았다.
- 검증 도구: `tools/visual-video-replay.mjs <영상> <저장소 밖 폴더>`. 제품과 같은 순서로 실제 영상을 처리하고, 예전 방식(화면 전체 OCR)과 비교한다.
- 테스트 162개 통과, 패키징 정상. 합성 영상에서 기대대로 동작했다.

## 남은 일 (우선순위 순)

1. **실제 강의 영상 검증.** `test_video`를 클라우드 세션에서 찾지 못했다. Google Drive에 1~2분 구간을 올리거나, PC에서 `tools/visual-video-replay.mjs`를 돌려 `report.json`과 `accepted/` 그림을 전달한다. 확인할 항목:
   - 슬라이드 전환을 놓치거나 잘못 잡는 비율
   - 판서 층의 정확도와 누적 중복
   - 짧은 판서가 캡처되는지(아래 3)
   - 페이드·확대 같은 오탐
   - 처리 시간
2. **2단계 회귀 수정.**
   - `richStructure` 오탐 수정: 제목 `Graph theory` 실패, `|x|`·`Pie chart`·`$5` 탈락.
   - 2단계 이전에 만든 보관 노트(본문에 `$…$` 포함)가 열리게 한다.
   - 2단계 테스트 근거를 `EvidenceStore`를 거친 실제 모양으로 바꾸고, 여러 줄 수식 보류 보장을 실제 경로에서 지킨다.
3. **짧은 판서 캡처 누락.** 지금 재캡처 기준(타일 하나의 3.5% 변화)으로는 "5V" 같은 짧은 판서가 캡처되지 않을 수 있다. 기준 화면 대비 판서 층이 일정 칸 이상 늘면 캡처하도록 바꿀지는 실제 영상 결과를 보고 정한다.
4. **판서 누적 중복.** 재캡처마다 그때까지의 판서 전체를 OCR한다. 읽기 순서가 흔들리면 같은 판서 글자가 근거에 반복된다. 직전 판서 층 대비 새로 생긴 부분만 OCR할지 실제 영상 결과를 보고 정한다.
5. **3단계 로컬 인식 비교.** 처리 시간·메모리·Whisper 동시 실행·Chrome 내장 AI는 사용자 PC에서 측정한다. 평가 설계:
   - 화면 한 장 단위로 평가한다.
   - 첨자·부호·분수·그리스 문자를 따로 채점한다.
   - 그림 영역 검출(존재 정확도)을 글자 인식과 분리해 측정한다.
   - 그림 재구성의 입력은 OCR 라벨이 아니라 영역 이미지다.
6. **사용자 결정 필요.** 손그림 판서(S–D 채널 그림 같은 스케치)를 노트에 어떻게 보일지 정해야 한다. "판서 있음 + 위치"만 표시할지, 잘라낸 이미지를 보일지다. 잘라낸 이미지는 이미지 저장 금지 원칙과 충돌한다.

## 작업 방식

- 조율은 Opus, 코딩은 Sonnet, 단순 작업은 Haiku가 맡는다(사용자 지시). Antigravity CLI는 클라우드 컨테이너에서 쓸 수 없다. Google 로그인이 필요해서다.
- 실제 강의 이미지, 영상, OCR 원문, 측정 결과물은 저장소에 커밋하지 않는다.
- `(판서) ` 접두어는 `lib/session.js`, `lib/openrouter-client.js` 프롬프트, `lib/summary.js`의 `simpleEquation`에 걸쳐 있다. `lib/ink-layer.js`는 `offscreen.html`에서 `lib/session.js`보다 먼저 로드한다. `memory.md`는 지침 파일이라 수정하지 않았다. 반영하려면 사용자 지시가 필요하다.
