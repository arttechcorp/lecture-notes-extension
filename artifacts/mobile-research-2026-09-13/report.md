# 모바일 랜딩 검증과 구성 제안

검토일: 2026-09-13 · 대상: [현재 Summrizei](https://summrizei.vercel.app/) · 비교: Alt, UnivAI, Tiro, Daglo

**결론: 모바일 레이아웃의 주요 경로는 작동하지만, WebKit에서 체험 패널의 복사 버튼이 작동하지 않는다. 이 문제를 먼저 고치고, 모바일 첫 화면은 완성 노트 확인 → PC에서 이어 쓰기 순으로 구성하는 것을 권한다.**

이 문서는 검증과 제안이다. 서비스 소스와 운영 배포는 변경하지 않았다. Terra 서브에이전트가 공식 문헌과 sandbox 문제의 수정 방향을 독립 검토했다.

## 1. 실제로 검증한 환경

카카오톡과 Instagram을 직접 실행한 결과가 아니다. 이 머신에는 사용 가능한 iOS Simulator 도구와 Android adb가 없었다. 공개 HTTPS 페이지를 실제 로드하고 macOS의 Playwright WebKit 26.6 및 Google Chrome 153.0.8010.36에서 터치·모바일 viewport·DPR 3·앱 식별 문자열을 조합해 검사했다. UA 문자열은 재현용으로 합성했으며 실제 앱에서 수집한 버전별 UA가 아니다.

| 프로필 | 엔진 | 기본 폭 | 기본 높이 | 정상 / 차단 조건 결과 |
|---|---|---:|---:|---|
| iOS + 카카오톡 UA | WebKit 26.6 | 375 | 660 | 각각 11/12 통과, 복사 실패 |
| iOS + Instagram UA | WebKit 26.6 | 390 | 660 | 각각 11/12 통과, 복사 실패 |
| Android + 카카오톡 UA | Chrome 153 | 360 | 660 | 각각 12/12 통과 |
| Android + Instagram UA | Chrome 153 | 412 | 660 | 각각 12/12 통과 |

8회 × 12검사 = **92/96 통과**. 남은 4개는 동일한 WebKit 복사 실패이며 독립적인 결함 4개가 아니다. 이 숫자는 인앱 브라우저 전체 호환율을 뜻하지 않는다.

검사항목은 페이지 가로 넘침, 메뉴 터치, 설치 안내·주소 선택, 학생 요금과 플랜 안내 일치, Free/Essential/Professional 예시 창 3종, FAQ, 후기 가로 스크롤, 복사 권한 거부, 화면 회전·CSS 본문 글자 확대, 정책 페이지에서 실제 뒤로가기로 돌아온 후 UI 재사용이다.

차단 조건에서는 Google Fonts·GSAP CDN을 차단하고 같은 출처 JavaScript 응답에 350ms 지연을 넣었다. 클립보드가 없는 환경도 초기 조건에 포함했지만 복사 검사 직전에는 모두 명시적 거절 API로 통일했다. 따라서 API 부재의 복사 분기는 별도 검증했다고 세지 않는다. viewport 높이 440px로 팝업 닫기를 확인하고, 844×390 회전 및 320px 폭을 검사했다. 이는 키보드·앱 툴바로 인한 공간 축소의 근사 조건이며 네이티브 키보드 실측이 아니다. `body` 20px 변경 역시 OS 글자 크기/200% 브라우저 확대를 완전히 대체하지 않는다.

별도 normal-motion 검사에서 두 엔진 모두 타이머 진행, 노트 생성, 정책 링크 방문 후 실제 history 복귀에서 타이머 진행을 확인했다. 관찰된 `pageshow.persisted`는 모두 false였다. **실제 bfcache 복원, 앱 백그라운드 복귀, OS 강제 종료 후 복원은 이번 증거에 포함되지 않는다.**

## 2. 발견한 P1: WebKit의 체험 복사 버튼

재현: 공개 페이지 → 완성된 예시 노트 → iframe 안의 복사 버튼을 터치한다. 한 번 또는 두 번 눌러도 부모의 재생 일시정지 상태가 바뀌지 않고, 선택할 textarea가 계속 숨겨져 있다.

브라우저 콘솔은 다음 원인을 직접 표시한다.

```
Blocked script execution ... because the document's frame is sandboxed
and the 'allow-scripts' permission is not set.
```

현재 iframe은 `sandbox="allow-same-origin"`이다. 부모 문서의 `hero-mockup.js`가 iframe 내부 버튼에 등록한 이벤트도 WebKit에서는 차단된다. DOM을 갱신하는 자동 시연은 보이지만, 내부 버튼은 작동하지 않는 차이다. 기존 Chromium 전용 검사로는 발견하지 못했다. 이번에는 탐색 완료·비동기 상태 변경을 기다리도록 테스트를 보정한 후에도 이 실패가 유지됨을 확인했다.

검증용 브라우저에서만 `allow-scripts`를 추가한 응답으로 바꾸면 복사 거절 시 fallback이 작동했다. 이는 원인 확인 실험이며 운영 수정안이 아니다. 같은 출처에 `allow-same-origin`과 `allow-scripts`를 함께 부여하는 방법을 권하지 않는다.

**권장 수정:** 복사 버튼을 부모 문서 소유로 옮기고 iframe의 sandbox는 유지한다. 부모 버튼에서 노트 값을 읽어 복사하며, 권한 거부 시 읽기 전용 textarea를 선택하고 안내한다. 내부의 작동하지 않는 복사 버튼은 숨긴다. 읽기 모드 버튼 등 다른 클릭 의존 UI도 함께 점검한다. `index.html`과 `hero-mockup.html`을 같은 구조로 유지한다.

폐기 가능한 브라우저 DOM에 부모 버튼만 추가한 실험에서는 sandbox를 그대로 유지한 채 **554/554자 선택, textarea 표시, 재생 일시정지**가 확인됐다. 소스 수정은 하지 않았다. 실제 iOS의 길게 누르기 메뉴와 다른 앱에 붙여넣기는 아직 미검증이다.

## 5. 현재 Summrizei에서 바꿀 우선순위

### P1 — 클릭이 안 되는 WebKit 체험 버튼

화면 구성을 바꾸기 전에 해결한다. 부모 문서로 인터랙션을 옮기는 방법은 위 실험으로 방향을 확인했다.

### P2 — 결과 노트를 보기까지 긴 거리

390px 폭 실측에서 헤더는 약 125px이며, 히어로 버튼 상단은 약 383px, 본격적인 노트 비교 섹션 제목은 약 1,984px, 플랜 제목은 약 4,949px였다. 폰트 로딩·애니메이션에 따라 값은 달라진다. 현재 축소 강의 화면과 540px 체험 패널이 먼저 이어져 첫 방문자가 얻는 결과를 확인하기까지 스크롤이 길다. 세로 배치로 가독성을 살린 장점은 유지하되, 결과 샘플을 앞에 두고 상세 시연은 접는다.

### P2 — 눌러 보기 전까지 PC 사용 조건이 드러나지 않음

첫 CTA의 무료 시작 문구는 모바일에서도 바로 사용할 수 있다는 기대를 만든다. 실제로는 PC 안내와 스토어 등록 준비 문구가 나온다. 지금 가능한 샘플 보기와 PC 사용 안내를 첫 화면에서 구분한다.

### P2 — 검증된 근거에 맞춘 신뢰 요소

현재 페이지의 대학 로고·학생 후기·성적 관련 문구가 어떤 증빙을 가진지는 저장소만으로 확인하지 못했다. 근거가 있는 실제 후기 2~3개를 우선하고, 출처가 불명확한 수치·성적 향상·학교 사용 주장은 확인 후 노출한다. 이는 다른 서비스가 노출하는 수치나 로고를 그대로 모방하지 않기 위한 콘텐츠 제안이다.

## 6. 권장 모바일 구성과 문구

별도 `/m` 페이지보다 같은 URL에서 모바일의 순서와 표현을 조정한다. PC와 기능·가격·정책의 의미는 같게 유지하고, 큰 브라우저 시연을 볼지 여부는 사용자가 선택하게 한다.

| 순서 | 콘텐츠 | 제안 문구·동작 |
|---|---|---|
| 1. 첫 화면 | 한 줄 헤더, 구체적인 가치, 두 CTA, PC 조건 | 제목 **강의는 집중해서 듣고, 복습은 정리된 노트로.** 설명: 온라인 강의의 화면과 설명을 함께 읽어, 핵심 개념과 복습 질문으로 정리해요. 주 CTA **완성 노트 보기**, 보조 **PC 사용 안내**. 하단에 **PC Chrome용 · 모바일에서는 예시를 볼 수 있어요.** |
| 2. 완성 노트 | 결과 카드 1개, 핵심 3줄, 개념 2개, 복습 질문 1개 | 원본 강의창보다 결과를 먼저 제시. **전체 예시 읽기**로 확장. 로그인·마이크 권한 없이 준비된 예시임을 표시. 본문 16px 안팎, 표는 해당 영역만 가로 스크롤. |
| 3. 차별점 | 화면과 음성을 함께 읽는 과정을 작은 카드로 | **슬라이드의 공식도, 말로 덧붙인 설명도.** 화면→설명→노트의 세 칸. 실제 인식 범위와 결과 품질을 넘는 보장 문구는 쓰지 않음. |
| 4. 사용 방법 | 세 단계, 선택형 시연 | 강의 열기 → 인식 시작 → 노트 검토. **작동 과정 보기**를 누르면 기존 시연을 펼침. 자동 반복 대신 명시적 재생·정지, 완료 후 읽기 유지. |
| 5. 믿을 근거 | 확인된 후기와 자료 처리 안내 | 실제 후기 소수와 출처. 로컬 인식 범위, 선택형 요약 기능의 처리 경로, 저장·보존 조건을 실제 제품 동작과 일치하게 표시. |
| 6. 플랜 | 짧은 결과 비교, 현재 이용 가능 여부 | Free / Essential / Professional를 결과 차이 위주로 비교하고 상세는 접기. 유료 결제·스토어 등록 준비 상태를 버튼 전에 보이게 한다. |
| 7. FAQ + 마지막 CTA | 모바일 가능 범위와 PC 연결 | 모바일에서 사용 가능한가요? 설치는 어디서 하나요? 자료는 어떻게 처리되나요? 마지막 CTA도 **PC 사용 안내**로 일치. |

히어로 이후에는 작은 하단 고정 CTA를 실험할 수 있다. 단, 첫 CTA가 화면에서 벗어났을 때만 표시하고 팝업이 열리면 숨긴다. safe-area 여백과 키보드 겹침을 실제 기기에서 확인한 뒤 채택한다. 처음부터 도입해야 할 필수 요소는 아니다.

### PC로 이어 쓰는 안내창

현재 상태에서는 다음이 가장 작은 구현이다.

- 제목: **PC에서 이어서 사용하세요**
- 설명: **Summrizei는 PC Chrome용입니다. 현재 Chrome 웹 스토어 등록을 준비하고 있어요.**
- 선택 가능한 주소와 **주소 복사** 버튼. 실패 시 주소를 길게 눌러 복사하도록 안내.
- 지원되는 경우 공유하기를 보조 수단으로 제공. 공유 API가 없거나 취소돼도 주소와 샘플은 남긴다.
- 스토어 등록 후에는 PC 설치 안내로 문구와 링크를 갱신.

Alt·Tiro의 이메일 전달 방식은 다음 단계 후보이다. 현재는 발송 백엔드가 없으므로 주소 복사만으로 시작하고, 모바일 방문자가 PC로 얼마나 이어오는지 확인한 뒤 추가한다. 외부 브라우저 강제 실행용 비공개 URL scheme에 전환을 의존시키지 않는다.

## 7. 측정 제안과 다음 실행 순서

1. sandbox를 유지한 부모 복사 버튼으로 P1 수정 및 WebKit 재검증.
2. 첫 화면 문구·완성 노트 카드·PC 안내를 먼저 적용. 나머지 콘텐츠는 아래로 이동하거나 접기.
3. 실제 iPhone/Android 각각에서 카카오톡과 Instagram의 네이티브 복사·뒤로가기·외부 브라우저 열기를 확인.
4. 모바일의 샘플 열기 → PC 안내 열기 → 주소 복사/공유 선택을 측정. 주소 복사 클릭을 PC 설치 완료로 계산하지 않는다. 이메일 발송을 붙이더라도 실제 PC 방문/설치와 구분한다.

제안의 목표는 긴 체험의 재생률보다 **결과를 이해하고 PC에서 실제로 이어 사용하는 비율**을 높이는 것이다. 이 개선의 전환 효과는 경쟁사 화면 관찰만으로 확정할 수 없으며 적용 전후 측정이 필요하다.
